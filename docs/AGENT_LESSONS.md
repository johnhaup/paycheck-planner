# Agent Lessons

Every lesson and pitfall learned in this repo, moved here verbatim from `docs/AGENT_CONTEXT.md`.
This file is not loaded into sessions. Before you touch a screen, component, build step or tool,
search it: `grep -n -i "<name>" docs/AGENT_LESSONS.md`. Add new lessons at the top, one bullet
each, ending with the issue id. Remove a lesson only when it has stopped being true.

- Android: a FlatList with a custom `StickyHeaderComponent` (`PinnedHeader`) rendered an empty content view (no header, no cards; hero and data were fine) until `removeClippedSubviews={false}` (2026-11-06, first Android build). Keep that prop on the Paychecks list.

- iOS launch arguments `-key value` land in the NSUserDefaults argument domain, so React Native's `Settings.get(key)` reads them with no native module (HAU-78). Maestro passes `launchApp: arguments:` keys verbatim as `key value` (no dash), so the flow keys must carry the dash themselves: `"-proStoreMock": true` reaches the app as `-proStoreMock true` (checked in the process argv with `ps`); an undashed `proStoreMock: true` silently leaves the mock off and Buy hits the real sandbox.
- An Expo SDK upgrade can silently break native-feeling behaviour that no type check sees. HAU-52 passed QA with the collapsing large title and pinned overview both broken; John found it in TestFlight. Those two are now a must-check on every QA run and a flow (`large-title.yaml`). Since HAU-113 the overview scrolls away and only the month pills stay pinned.
- Large titles only collapse when the scrolling view is the screen's root and uses `contentInsetAdjustmentBehavior="automatic"`. A FlatList wrapped in a View loses it.
- StoreKit testing: the `.storekit` configuration reaches the simulator only through Xcode's run action. From a `simctl` launch, Buy goes to the real App Store sandbox and raises a "Sign in to Apple Account" alert that Maestro cannot see and that survives `clearState` relaunches, so every later flow fails at Welcome. That kept purchase steps out of `.maestro/qa/` until HAU-78; the gate now buys on the mock store (`-proStoreMock`). A failed mock flow that reaches the real Buy leaves the same alert, so dismiss it (`tapOn: point: "33%,60%"`) before re-running.
- The App Store Connect product stays "Missing Metadata", and purchases fail in TestFlight, until a review screenshot of the paywall is attached.
- `expo run:ios --device <udid>` ends with an `osascript` call that hangs while a macOS Automation prompt waits on John's desktop. For a Release build to install by hand, build with `--device generic --output <dir>` and `simctl install` instead.
- Dev builds load JS from Metro on 8081 only after `clearState` (it wipes `RCT_jsLocation`). Start Metro on 8081 before running the suite against a Debug build; a Release build needs no Metro (it has `main.jsbundle` in the app container).
- Maestro: Settings rows with a chevron have labels ending in ", " so match with `".*Erase all data.*"`. The month chart columns match only by their accessibility label (`"September 2027, $5k left"`). Sample data comes from "Try with sample data" on the empty Paychecks tab. Past paychecks' title is "Past paychecks", not "History".
- A fresh install is Dark whatever the OS appearance says (`themeStore` default).
- Never open the Xcode app from an agent shell. A GUI Xcode holding a worktree's workspace leaves dialogs on John's screen when prebuild regenerates `ios/`.
- Flows in `.maestro/qa/` run on a loaded Mac in the release gate: use `extendedWaitUntil` on the element the next step needs with 10-20 s timeouts, never fixed sleeps. A flow that only passes on an idle machine is a flake.

- A gate ticket whose log has no `[Failed] <flow>` line and no `report.xml` never ran a flow. Read `~/Projects/linear-runner/.stamps/gate-<slug>-<date>/maestro.log`: `IOSDriverTimeoutException` / "iOS driver not ready" or "Device … is not connected" mean Mac load or a dropped simulator, not an app regression. Check `~/Library/Logs/linear-runner.log` for an earlier PASS at the same sha and for another gate starting the same minute (HAU-99).

- The `<App> Release Gate` simulator belongs to `gate.sh` alone: no agent builds, installs, launches or runs Maestro on it, even when no gate is running at that moment, because a long `expo run:ios` outlives the check and the next tick's gate starts on top of it (HAU-102). A gate whose first try fails with `DeviceUnreachableException` or a screen the flow never navigated to, and whose retry passes, points at a second user of the simulator: grep the agent transcripts in `~/.claude/projects/*/` for the gate simulator's UDID.
- Undo toasts (`withUndo`, sonner-native default) dismiss themselves after 4 s. In a flow, tap Undo straight after `extendedWaitUntil: visible: "Undo"` with no screenshot or other step in between: under gate load a single step can take 2-10 s (HAU-102).

- `scrollUntilVisible` is time-boxed (default 20 s) and its first lookup alone can eat that budget under gate load, so it fails one swipe short (HAU-106). It also never looks again after its last swipe: two lookups and two swipes took 22.8 s and it failed with the element on screen (HAU-173). When the target sits at a known end of a screen, swipe there explicitly and `extendedWaitUntil` the element instead.
- A "simulator build" gate ticket whose build.log ends in `devicectl list devices … --timeout 5 exited with non-zero code: 2` is host load, not a build break: Expo CLI lists physical devices with a hardcoded 5 s `devicectl` timeout before it compiles anything, even with `--device <sim udid>` (HAU-110). Check the runner log for an earlier gate PASS at the same sha.
- No ordering of steps keeps a 4 s Undo toast reachable under gate load: Maestro alone can spend 4-5 s between a tap and the next tap (HAU-112). A flow that has to hit a timed toast needs a retry that puts the state back (`repeat: while: notVisible:` on what the toast's action restores), not just a tight step order. Make the toast's wait and tap `optional`, or a toast that is already gone fails the flow before the retry runs. When the missed action leaves another screen (Erase all data → Welcome), the retry has to rebuild the state first (HAU-153). `maestro check-syntax <flow>` checks a flow's YAML with no simulator.

- No native change? Verify a JS change on a simulator that already has a Release build installed without rebuilding: `bunx expo export:embed --platform ios --dev false --entry-file index.ts --bundle-output <tmp>/main.jsbundle --assets-dest <tmp>/assets`, copy it over `main.jsbundle` in `simctl get_app_container <udid> com.johnhaup.paycheckplanner`, relaunch (HAU-116). `sips -c` crops around the centre and ignores `--cropOffset`; resize screenshots with `sips -Z` instead.
- A "Build failed" ticket whose log ends in `Workingdir is not empty` after the gate passed is a stale EAS local working dir left by a killed build, not an app break. linear-runner clears it before each build since `45b6e07` (HAU-135). If it comes back, check `~/.cache/eas-local-build/<slug>` and whether another build of the same app was running.

- Never put a percent `width`/`height` on an absolutely positioned child of a view with padding: RN's Yoga errata (`AbsolutePercentAgainstInnerSize`) resolves it against the size without the padding. Use `absoluteFill` alone (`left`/`right`/`top`/`bottom`). On `react-native-svg`'s `Svg`, leave out the width and height props for the same reason (HAU-147).
- A horizontal ScrollView clips vertically too: anything that overflows a fixed-height child is cut at the scroll view's edge. Let text-bearing children set the height (`minHeight`, not `height`) instead (HAU-156).
- An absolutely positioned child with no `right` or width is limited to its parent's width, so a tag hanging off a small fixed-size control wraps as soon as its text outgrows the control. Give it one line and a cap (HAU-160).
- A row with a label and an amount side by side cannot survive iOS accessibility sizes (text up to 3.57×: a 15pt amount is about 54pt tall). Stack it with `useAccessibilityTextSize()`; do not just truncate the label. Cap text with `maxFontSizeMultiplier` only inside a fixed-size box (date tile, Go Pro card), and pair it with `adjustsFontSizeToFit` (HAU-131).
- A horizontal ScrollView's `scrollTo({ x })` and `contentOffset.x` are measured from the content's left edge in RTL as well, so the resting position is `contentWidth - viewportWidth`, not 0, and the first child is at the right. Math written from the start edge has to convert both ways: `contentSize.width - layoutMeasurement.width - x` (HAU-166, `RCTScrollViewComponentView.mm` in RN 0.88; Android reports `scrollX` the same way).
- Text with no `textAlign` is not "start": on iOS in an LTR layout it follows the device language, so an Arabic device with English picked right-aligns it (HAU-167). Every `Text` needs an alignment; `AppText` sets `"start"`, so third-party text (sonner-native) and any raw `Text` need it by hand. A `TextInput` never learns the layout direction on iOS, so `"start"` and `"left"` both mean physical left there: use `I18nManager.isRTL ? "right" : "left"`. A nested `AppText` carries its own `"start"`, so inside a centred parent pass `center` to the child as well.
- A formatted amount in Arabic or Hebrew is a bidi string (RLM, number, NBSP, symbol), and its display order is decided per character. Adding a Latin letter or a bare `-` to it, or slicing it, can move the currency's letters or the sign: let `Intl` place the sign, and close a number you extended with an RLM (`\u200F`) (HAU-154). The order can be checked with no simulator: lay the string out with CoreText in a Swift script (`CTLineCreateWithAttributedString`, sort the glyphs of `CTLineGetGlyphRuns` by x) and feed it `NumberFormatter`'s output, which has the same marks as the app's.
- React Native's sticky header wrapper (`stickyHeaderIndices`) keeps the header's full layout height at the list's top and sits above the rows. Moving the header's content inside it with a transform leaves the rest of the wrapper as an invisible box that swallows touches while scrolling still works (HAU-155). To pin anywhere but the list's top edge, pass a `StickyHeaderComponent` that moves itself (`PinnedHeader`); do not shift the child. The sticky child is `VirtualizedListCellContextProvider`, so `ListHeaderComponentStyle` (and a `pointerEvents` in it) never reaches the wrapper.

- A pinned footer over a ScrollView: `position: absolute` at the bottom, `onLayout` height into the list's `paddingBottom` and `scrollIndicatorInsets`, a gradient above it with `experimental_backgroundImage` (RN 0.88 parses `#RRGGBBAA`, so a palette colour with `00` alpha is the transparent stop). Footer text caps at 1.5×; the title and list text cap where the longest localized word (every key the element can show, the unlocked title included) fits a 375pt row, measured with CoreText (HAU-182, HAU-158). The paywall is the reference in this repo.
