# HAU-539: sentence case for buttons and titles (2026-11-17)

## What changed
- Copy only, no code. Every Title Case button, screen title and form label in `en.json` is now
  sentence case, matching Welcome, the empty states and Settings: `common.selectDate/selectTime`,
  `screens.incomeSource/payDate`, `income.form.*` (labels, Add/Update income source),
  `expenses.form.*` (labels, Add/Update expense, Add/Update set-aside), `payDate.oneTime.*`
  ("Add one-time expense"), `pro.restore` ("Restore purchases", and the footnote that names it),
  `settings.region` ("Language & currency").
- Locales that had copied the English Title Case got the same treatment for those keys plus
  `screens.currency` / `settings.currency`: id, ms, tr (all keys), el and vi (`settings.region`).
  German keeps its noun capitals; every other locale was already sentence case.
- Left alone on purpose: product names ("Paycheck Planner Pro", "Family Sharing"), sample payee
  names in `demo.*` (they are user data, not UI), single-word titles.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Release build (`expo run:ios --configuration Release`) on `Paycheck Planner Dev`: all six
  `.maestro/qa/` flows run one by one; screenshots show "Income source", "Add income source",
  "Payment link (optional)", "Linked income source", "Pay date" next to "Mark all paid",
  "Restore purchases".

## Flows
- `.maestro/qa/` still spells the old strings ("Add Income Source", "Update Expense",
  "Restore Purchases", "First Month") and still passes: Maestro's text matching ignores case.
  QA may update the spelling to match; nothing is broken.

## Pitfalls
- On 2026-11-17 another session ran Maestro on `Paycheck Planner QA 27` at the same time, and a
  different build (old strings, plain-JS bundle) replaced mine mid-run; my screenshots there showed
  "Pay Date". Compare `main.jsbundle`'s md5 in the app container before and after a run, and use
  `Paycheck Planner Dev` for engineer checks. Running the folder (`test .maestro/qa/`) on one
  simulator ran the flows together and all failed; run them one file at a time.
- On this Mac `Paycheck Planner QA 27` is `E48CA593-50B9-4752-8463-B4B436CE3A9A`; AGENT_CONTEXT's
  UDID is from another machine. Look it up with `xcrun simctl list devices`.
- A fresh worktree has no `node_modules`: `bun install` before `tsc`, or it reports thousands of
  bogus errors.
