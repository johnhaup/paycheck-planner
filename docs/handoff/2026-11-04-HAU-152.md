# HAU-152: Arabic, Hebrew and Urdu mirror the layout (2026-11-04)

Moved here from `docs/AGENT_CONTEXT.md` when the branch merged `origin/main` on 2026-11-12 (recent work
is one note per ticket now). The large-title bug QA found on this branch is in `2026-11-12-HAU-165.md`.

## App
- iOS only reports an RTL app language when the language is declared, so `app.json` gives
  `expo-localization` `supportedLocales` (all 45), which writes `CFBundleLocalizations`. This also turns on
  the per-app Language row in iOS Settings and localizes system UI.
- The in-app picker can differ from the device, so `localeStore`'s `applyLayoutDirection` calls
  `allowRTL`/`forceRTL` and `reloadAppAsync` when language and `I18nManager.isRTL` disagree, on a language
  change and after hydration.
- What does not mirror by itself: `AppToggle`'s thumb (transform), chevrons (`FORWARD_CHEVRON`), the swipe
  actions (`AppSwipeActions` props are now `startAction`/`endAction`) and the native tab bar on a forced
  direction (`unstable_nativeProps.direction`).
- `useLocale().isRTL` had no readers and is gone.
- Native change: needs a real build, a bundle swap cannot show it.

## Verified
- tsc, lint, `expo config --type introspect` (45 `CFBundleLocalizations`) and a throwaway macOS bundle (the
  key gives `preferredLocalizations` `["ar"]`, like `.lproj` folders). QA then ran it on
  `Paycheck Planner QA 27` and added `.maestro/qa/rtl.yaml`.

## Lessons
- iOS RTL needs the language declared: without `CFBundleLocalizations` (or `.lproj` folders) the app's
  language is English and `I18nManager.isRTL` stays false on an Arabic device, whatever `allowRTL` says.
  Native tab bars and transforms ignore `forceRTL`, and `I18nManager.isRTL` only changes on reload, so read
  it at module scope freely but never gate on the language.

## Open follow-ups
- With an in-app language that differs from the device, UIKit alerts and pickers keep the device's direction
  until the user also changes it in iOS Settings.
- The English flows' point taps (`25%,15%`, `65%,15%`) assume LTR; an Arabic flow needs its own taps.
