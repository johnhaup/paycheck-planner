# HAU-330: Past paychecks PRO badge and chevron wrap together (2026-11-14)

## What changed
- `app/history.tsx`: the PRO badge and the chevron in the "See earlier months" row sit in one
  row `View` (`unlockTrailing`, same `md` gap). The wrapping row now has two flex items, the
  label and that group, so the wrap can no longer break between the badge and the chevron
  (at Accessibility L the label and badge fitted on line one and the chevron fell alone to
  line two).

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean.
- `Paycheck Planner Dev` simulator (iOS 27), Release app with this branch's `export:embed`
  bundle, free tier, dark, English, sample data, `paycheck-planner://history`. Screenshots read:
  - default and Accessibility M: label, PRO and chevron on one line.
  - Accessibility L (the reported size) and XL: label on line one, PRO and chevron together,
    centred, on line two.
  - Accessibility XXXL: label on two lines, PRO and chevron together under it.
  - At Accessibility L the row still opens the paywall.
- Not run: the `.maestro/qa/` suite, light mode, other languages, RTL.

## Follow-ups / pitfalls
- At Accessibility L the badge alone would still fit beside the label; it now drops with the
  chevron instead. That is the "both on the second line" outcome the ticket allows.
- The open continuous-list PR removes the History screen and moves "See earlier months" into
  the Paychecks list; whichever merges second must carry this grouping over.
- A `flexWrap` row breaks between any two children: group things that must stay together
  into one child.
- A shell loop that builds `UICTContentSizeCategory…` names wrongly gives an unknown category,
  which iOS silently treats as the default size; check the launch line in Maestro's output.
