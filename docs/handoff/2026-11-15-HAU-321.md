# HAU-321: free cold launch lands under the current paycheck again (2026-11-15)

## Cause (measured, not the one the ticket guessed)
- Logged on `Paycheck Planner Dev` (Release, sample data backdated to 2026-07-03 / 07-15): the opening
  jump lands exactly (offset 397.7 = Nov 20's cell y 809.3 − pinTop 106 − header 305.7). About 40 ms
  later, still hidden, iOS moves the list to 281.7 (−116pt) on its own. All scroll events arrive in
  one burst ~350 ms after the jump, after `JUMP_CONFIRMS` has run out, so nothing corrected it.
  Most likely iOS applying the navigation bar inset at mount after our scroll.
- Pro only looked right because `isPro` arrives after the list mounts, changes the rows and runs
  the jump a second time. Tab return re-jumps once everything is settled.
- "See earlier months" was not the cause: its height was measured in the first layout pass.
  Making it its own data row (John's first suggestion) was tried and gave the same 116pt offset on
  cold launch, so it was reverted.

## What changed
- `app/(tabs)/(paychecks)/index.tsx`: while the opening jump is hidden, a scroll event that moves
  the list runs the jump again (`handleHiddenScroll` → `rejump`, at most `MAX_REJUMPS` = 5 per jump),
  and the list is shown 150 ms after the last scroll event (the show timer is now debounced).
  `rejump` is a ref set in an effect: `handleScroll` has to stay above the hooks that take its
  shared values (React Compiler lint, `react-hooks/immutability`), so it cannot name `attemptJump`.

## Verified (Dev sim, iPhone 17 Pro, iOS 27, HAU-366's Release app + `export:embed` bundle swap)
- Base bundle: 4/4 cold launches about 116pt low (tail of Nov 13 above Nov 20). Fix: 8/8 land with
  Nov 20 right under the header, pixel-identical below the header, same spot as a tab return.
- Pro (mock store, bought on the same data): 4/4 cold launches land under the header.
- Scrolling up still reaches "See earlier months" and the expanded large title.
- `bunx tsc --noEmit`, `bun run lint` clean. `.maestro/qa/` 6/6 on the Dev sim with the fix bundle.

## Pitfalls
- `console.warn` from a Release bundle shows in `simctl spawn <udid> log stream --predicate
  'eventMessage CONTAINS "<tag>"'`: the quickest way to time scroll events against jumps.
- `topOffset` takes the first scroll event, which on this cold launch is the jump's own offset, not
  the expanded-title rest. See follow-ups.

## Follow-ups
- Not fixed here, already on `main`: free with backdated sources, after a cold launch, tapping Dec
  then Nov lands on Nov 20 instead of the top of November. A jump to row 0 scrolls to `topOffset`,
  which here is 397.7 (the opening jump's offset). It needs a top offset that does not depend on
  which scroll event comes first.
