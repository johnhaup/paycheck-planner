# HAU-438: FAB bounces in and out (2026-11-16)

## What changed
- `AppFab` (Income and Expenses) is now an animated `Pressable` whose scale follows
  `useIsFocused()` from expo-router: it springs 0 → 1 (`dampingRatio` 0.5, 500 ms, one overshoot)
  when its screen comes to the front, and swells to 1.1 then shrinks to 0 (90 + 160 ms) when the
  screen loses focus. Native tabs keep every tab mounted, so focus, not mount, is the trigger.
- Losing focus also covers the Add Income Source / Add Expense modals: the FAB shrinks away as the
  sheet slides up and bounces back in when it closes.
- Reduce Motion: Reanimated's default `ReduceMotion.System` jumps straight to the end value.
- No new strings, no new dependencies (Reanimated 4 was already in use).

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Release build on a scratch iOS 27 simulator (HAU-439 was building onto `Paycheck Planner Dev` at
  the same time), recorded with `simctl io recordVideo` and read frame by frame: on a tab switch
  to Income/Expenses the FAB grows from a dot past full size and settles (~0.4 s); opening Add
  expense shrinks it to nothing in ~5 frames; dismissing the sheet bounces it back in. The FAB
  sits at full size in the settled screenshots (Income empty state, Expenses).
- `.maestro/qa/` smoke, income (incl. the gated `Add income source · PRO` FAB), expenses: 3/3 pass.

## Notes / pitfalls
- A tab switch in the native tab bar hides the old screen at once, so the bounce *out* is only
  visible where the screen stays on screen (a modal presenting over it). Leaving Income for
  Paychecks shows no exit animation; the FAB is already at 0 when you come back, so it bounces in.
- Maestro taps the FAB after `waitForAnimationToEnd`/its own settle, so the flows need no change.
