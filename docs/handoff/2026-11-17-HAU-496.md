# HAU-496: Android build failed @ 8dc033c (submit)

## What happened

The Android run of `main` @ `8dc033c` (`builds-android/paycheck-planner/2026-11-16-210607` on the
Linux worker) passed the gate (5/5 flows, `report.xml` has 0 failures), built and signed the AAB
(version code 6), and failed only at `eas submit`: "The Google service account cannot submit this
app." Nothing in the app or the flows was broken. The Play Console app did not exist yet.

On 2026-11-17 John created the Play app and gave the service account access to all apps.

## What changed

Docs only. `docs/AGENT_CONTEXT.md` said the Play Console app does not exist and that `eas submit`
fails until it does; both lines were no longer true and are corrected. No code, config or flow change:
`eas.json` → `submit.production.android` (key path, `internal`, `draft`) was already right.

## How it was verified

Queried the Play Developer API with the app's service account key
(`~/linear-runner-worker/keys/paycheck-planner/credentials/android/service-account-key.json`):
- `edits.insert` for `com.johnhaup.paycheckplanner` returns 200 (it was the call Google refused).
- The internal track holds release `3 (1.1.0)`, version code 3, status completed.
- The edit was deleted again; nothing was uploaded or changed in Play.

EAS's remote version code is at 6, so the next build is 7, above the 3 that Play holds.

Not verified: an actual `eas submit` upload. That happens on the first Android run after this merges.

## Lessons

- On the Linux worker the keys are in `~/linear-runner-worker/keys/<app>/`, not `~/Projects/_keys/`.
- "Cannot submit this app" can be checked without building: an `edits.insert` with the service
  account answers in a second (404/403 while the app or the permission is missing, 200 after).

## Follow-ups

- linear-runner (not this repo): a submit failure with a green gate should not file an "Android
  build failed" ticket that asks whether the app or a flow is broken, and should not hold builds
  behind a merge when the cause is in Play Console.
