# HAU-458: Expenses filter switch swaps rows instead of sliding them (2026-11-16)

## Problem
HAU-446's `AppAnimatedListCell` (FadeIn / FadeOut / LinearTransition) ran on every change of the
Expenses SectionList, filter included: rows leaving faded out in place while the staying ones
slid through the same space, so for ~0.3 s two rows' text drew on top of each other.

## What changed
- `src/components/AppAnimatedListCell.tsx`: the cell reads `ListCellAnimationContext` (default
  `true`) and drops `entering`, `exiting` and `layout` when it is `false`. `useListSwap()` returns
  `{ animated, swap }`: `swap(change)` turns the cells' animations off in one commit, applies
  `change` in the next (from an effect), and turns them back on 100 ms later.
- `app/(tabs)/expenses/index.tsx`: filter, sort (action sheet and Android alert) and search go
  through `swap`; the list is wrapped in `ListCellAnimationContext.Provider`. Adds and deletes
  still fade and slide. Income and paycheck detail unchanged (they have no filter).

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Release build on QA 27 (iOS 27, dark), sample data, `simctl io recordVideo`, changed frames
  only (`mpdecimate`): All → One-time → All → Recurring → All jumps straight from the old list to
  the new one, no in-between frame. Deleting Savings still fades it out and slides Mesa Health up.
- `.maestro/qa/` 6/6 on that Release build.
- Not checked: Reduce Motion, sort and search by video (same `swap` path as the filter), a device.

## Pitfalls
- Reanimated takes a removed view's `exiting` from its last committed props. Switching the
  animation off in the same render that removes the rows still fades them out; the cells need a
  commit with no animations first. React Native has no `flushSync` (that is react-dom), hence
  the effect-driven second commit.
- Keying the list on the filter would also stop the animation but remounts the root scroll view,
  which owns the collapsing large title; avoided.
