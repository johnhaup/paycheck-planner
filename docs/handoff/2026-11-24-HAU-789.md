# HAU-789: Arabic amounts read "US$", not "$US"

## What changed and why
- Arabic amounts come out of `Intl` as `RLM 1,270.15 NBSP US$`. The trailing `$` is a neutral
  between Latin "US" and the end of an RTL paragraph, so it took the RTL direction and was drawn
  left of "US" ("$US").
- `closeNumber` moved from `src/utils/money.ts` to the pure `src/utils/rtlAmount.ts` as
  `closeAmount`, so `bun test` can import it. Besides the RLM after the number (HAU-154/HAU-172),
  it now appends a left-to-right mark (U+200E) when an RTL-marked amount ends in a Latin letter
  plus symbol characters (`US$`, `CA$`, `R$`). `€`, Hebrew `‏$`, `ج.م.‏` get no LRM.
- `formatMoney`, `formatCompactMoney` and now `formatMoneyIn` (Currency sheet preview) use it.
  `splitMoney` is unchanged; the LRM rides in `cents`.
- Earlier notes and the brain's `features.md` describing "$US 4.8k" / "$US -292.84" as correct
  are superseded: the correct reading is "US$ 4.8k" / "US$ -292.84".

## Verified
- `src/utils/rtlAmount.test.ts` (literal strings, no ICU dependency): Arabic USD, negative,
  compact, Hebrew CAD get the LRM; Hebrew USD, Arabic EUR/EGP do not; LTR strings unchanged.
  Also checked against Bun's real ICU for ar/he/en/de/ur with USD, CAD, BRL, EUR.
- `bun test`, `bunx tsc --noEmit`, `bun run lint` pass.
- Dev build on Runner 1, sample data, `-AppleLanguages`: Arabic Dark and Light Paychecks show
  "US$ 1,270.15", "US$ 4,130.00 دخل · US$ 2,859.85 مخصص", chart "US$ 5k"/"US$ 1.3k", card
  "US$ 1,980.00", "US$ 883.00 متبقي", bill rows "US$ 220.00". English, German, Hebrew unchanged.
- Not checked: Android (no emulator on this Mac; same JS string logic), the Arabic Currency
  sheet and a short-paycheck negative on screen (covered by the unit test only).

## Follow-ups / pitfalls
- `.maestro/qa/paychecks.yaml` line 296 full-matches `… US\\$` and now needs `‎`
  appended (left for QA per the plan).
- Arabic amount strings (accessibility labels, notification text) now end in an invisible
  U+200E; anything that full-matches one must allow for it.
