# HAU-642: Settings toggle rows taller than link rows

## What changed and why
- `SettingsLinkRow` had 16 pt padding around one line of body text (~50 pt); `SettingsToggleRow` has the
  same padding around the 28 pt `AppToggle` track (60 pt), so the Settings list had two row heights.
- `AppToggle` now exports `TOGGLE_HEIGHT` (28, still the track height) and `SettingsLinkRow`'s row
  style sets `minHeight: TOGGLE_HEIGHT + spacing.lg * 2`. The row already centres its content
  (`alignItems: "center"`), so label, value, Pro badge and chevron sit in the middle.
- `minHeight` only raises a floor: the stacked layout at accessibility sizes is taller than 60 pt
  already and is unchanged, as the issue asked.

## Verification
- Runner 1 (iPhone 17 Pro, iOS 27.0), dev build on Metro, default text size. Settings in Dark:
  Hide cents and Language/Currency/Pro rows all measure 136-137 px in the screenshot (~60 pt).
  Light, scrolled down: Auto-mark paid, Back up, Restore, Export CSV (Pro badge), Erase all the same.
- `bunx tsc --noEmit`, `bun run lint` clean. No unit tests in the repo; no flow changes needed.

## Follow-ups
- Corner radii still differ: toggle rows are `AppCard` (radius.card, 20) and link rows use
  radius.lg (10). Visible in the issue's screenshot; out of this ticket's scope (height only).
