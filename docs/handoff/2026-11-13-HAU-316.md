# HAU-316: Paychecks is one list through every month (2026-11-13)

## What changed
- `app/(tabs)/(paychecks)/index.tsx`: the list holds every month's paychecks, oldest first (free: this
  month and next; Pro: six months back to eleven ahead). The selected month (hero and chart) is the
  last month whose title reached the pinned header's bottom edge; `PaycheckCell` (the list's
  `CellRendererComponent`) records each month's top in a shared value for that.
- Opens on the paycheck nearest today ("home"): at launch, when income returns after Erase all data,
  when rows are added before it (buying Pro), and when the tab is selected again (`useSegments`, so
  closing a sheet or the pay date screen does not move the list). Chart taps, the calendar icon and
  the shortfall line jump the same way (`jumpTo`), putting the row just under the whole header.
- The header no longer collapses by distance from the top (the hero would only ever show at the earliest
  month): scrolling forward collapses it to the pills, scrolling back brings it out, anywhere in the list.
- Past paychecks moved into the list, so the "Past paychecks" link, `app/history.tsx`,
  `buildPastMonthGroups` and three strings (45 locales) are gone. `buildMonthGroups` takes
  `monthsBack`. The current month's totals now cover the whole month, not only what is still to come.
- Free tier: `ProUnlockRow` after the last row ("See a full year of paychecks") and, only when a
  source was paying before this month, before the first ("See earlier months"). Existing strings.
  `MonthBarChart` opens with the selected month at the start (Pro's chart begins six months back).

## Pitfalls
- Every row stays mounted (`windowSize` 1000). With rows left out the list estimates heights and a
  landed jump drifts as real ones come in; the selected month also needs every month's top.
- A scroll asked for from JS can be carried out over a second later while the list mounts rows, so
  nothing after a jump is timed: the jump state ends on the next drag (or status-bar scroll to top).
- Reanimated's `Animated.FlatList` takes `CellRendererComponent` for itself; hence `createAnimatedComponent(FlatList)`.
- A shared value set from JS reads back as its old value until the UI thread has it: `jumpTo` set
  `jumping` and the attempt read it straight back as false, so a jump after a drag did nothing unless
  a header layout re-ran it (Welcome opened under a collapsed title after Erase all data). `jumpingRef`.
- `CI=1 expo start` does not watch files: edits are not served until Metro restarts.
