# HAU-629 Duo: empty strip above the Paychecks hero after the first fold walk

## What changed and why
- Cause (from scroll logs on a Duo): on a launch folded, the list's first scroll event reports y = -58
  (a passing layout with the large title on) even though the screen has no large title there (top inset 0,
  `pinTop` 0). The list kept that as `topOffset`, its "top of the list" for jumps. After the walk a jump to
  row 0 runs (the Paychecks home row with sample data) and scrolled to -58: the 58 pt strip, gone on the
  first drag. A repeated walk did not show it because the jump already sat there; not an UIKit leftover
  from the upright pose as the issue guessed.
- `app/(tabs)/(paychecks)/index.tsx`: `topOffset` takes the first event's offset only while there is a
  large title (`pinTop > 0`); without one the list starts below the bar and its top is 0. A standard
  iPhone and Android take the same path as before (iPhone: pinTop > 0; Android's first offset is 0).

## Verified
- `bunx tsc --noEmit`, `bun run lint`; `.maestro/qa/` on Runner 1 (iPhone 17 Pro, Debug + Metro 8082): 6/6.
  Runner 1 Paychecks top: large title expanded, hero under it, as before.
- Own Duo (iPhone Duo, iOS 27.1, duoctl v0.2.1, `RUNNER_SIM_UDID=<duo> runner devapp`), fresh install each
  run, folded, sample data, then open, landscape, portrait, landscape, close, portrait. Before the fix the
  hero moved down 58 pt (reproduced). With it, 2 of 2 fresh launches: before and after screenshots match,
  logs show every jump to row 0 at offset 0. Duo deleted afterwards.
- Dark only: the change is a scroll offset, no colours. Empty state has no list header, unaffected.

## Follow-ups / pitfalls
- Still open from HAU-568: unfolding upright after a folded launch shows the large title collapsed. The
  resting offset upright (-140 here) is never recorded, since `topOffset` is taken once per mount;
  a per-pose top offset would fix both.
- duoctl `tap` worked on the first try for "Try with sample data" (190, 474 folded); `elements`
  (axe describe-ui) timed out on a freshly booted Duo.
- Fresh state on the Duo without Maestro: `simctl uninstall` + `simctl install` the Runner 1 app container.
