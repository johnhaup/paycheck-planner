# HAU-875: Android Pro cannot be bought (paywall never loads the Play product)

**Cause:** the paywall spun or errored because Play could not serve the product on the sideloaded `runner` emulator. The product does exist in Play (active; set to $2.99 on 2026-11-26). The earlier "does not exist" came from an old
repo note; creating it failed with 403 while the service account's Google Cloud project was deleted (HAU-849).

**Changed (code):**
- `app/paywall.tsx`: price state is `loading | loaded | failed`. A fetch that resolves without the product (Play
  reachable, product missing or inactive) now shows the error + Try again instead of spinning forever. A failed
  store connection (`onError` while loading) shows the error too; Try again calls `reconnect()` when not connected,
  otherwise re-fetches.
- `pro.footnoteAndroid` in all 45 locales: the footnote minus "Family Sharing is included" (Play Family Library
  does not share in-app purchases); de says "neues Handy" instead of "neues iPhone". iOS keeps `pro.footnote`.
- `src/services/proStoreMock.ts`: `reconnect` added to `ProStoreConnection` (mock returns true).
- Decision recorded in brain `apps/paycheck-planner/decisions.md` (2026-11-26).

**Verified:** `bunx tsc --noEmit`, `bun run lint`, `bun test` (39 pass). Release APK (`expo prebuild` +
`gradlew assembleRelease -PreactNativeArchitectures=x86_64`) sideloaded on the `runner` emulator (API 35, Play
Store present, `-no-window -gpu swiftshader_indirect`; the windowed emulator fails on a missing Qt xcb plugin).
`paycheck-planner://paywall`: error + Try again, Android footnote; Try again shows the spinner, then the error;
Restore purchases shows "Couldn't reach the store"; process alive, no FATAL in logcat.

**Verified later the same day, from Google Play (version code 12, without this PR),** on the `play-test` AVD
(android-36 `google_apis_playstore`, tester account signed in; `runner` has `PlayStore.enabled=no`): $2.99, test
purchase, Pro after relaunch, Pro on a fresh install without tapping Restore, refund locks Pro. After the refund the
first relaunch stayed Pro; it locked after `pm clear com.android.vending`. The upload service account cannot read or
refund orders (401): refunds are done in Play Console. Start the AVD with `-gpu swiftshader_indirect` (host GPU
rendered black on `auto`).

**iOS (merged with `main`, Release on an iOS 27.0 simulator, mbp-512):** `.maestro/qa/pro.yaml` passes; without the
mock store the paywall loads "Buy for $2.99" with the Family Sharing line.

**Pitfall:** Play's "Service connection is disconnected" (-1) on a sideloaded APK is reported by `fetchProducts`,
after `connected` is already true; the Restore button is therefore enabled and fails with `service-disconnected`.
