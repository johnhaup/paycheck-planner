# HAU-810: Android gate failed at expenses' post-relaunch QA Water step

**Cause: an app regression on Android, not a stale flow.** Since HAU-446, on Android, any Expenses
list cell mounted after the SectionList's first batch stays at `FadeIn`'s opacity 0. The relaunch step
that HAU-791 added was the first thing to exercise this: after the relaunch, QA Water, Streaming and
Car Registration mount late, so they are never drawn. The data is all there: Mesa Health's header
reads $1,849.39/mo including the blank Streaming row, and logcat lists "Skipping invisible child"
with full row bounds where the rows belong. Rows from the first render (under `skipEntering`) and
rows mounted while `useListSwap` has animations off were always visible.

**What changed.**
- `src/constants/motion.ts`: on Android `ROW_ENTERING` is `undefined`, so rows appear with no fade.
  The exit fade and layout spring are unchanged, and iOS is unchanged. Both users, `AppAnimatedListCell` and
  `PaycheckExpenseRow`, already accept `undefined`.
- `AppAnimatedListCell` doc comment notes that the entering fade is iOS-only.
- `.maestro/qa/expenses.yaml` is untouched; its post-relaunch `.*QA Water.*` wait is the guard.

**Verified (emulator Pixel_9_Pro, Release APK built the gate's way: prebuild --clean, assembleRelease x86_64).**
- Before the fix: `expenses.yaml` fails at the same step, and the screenshot ends at Phone with blank space below.
- After: `expenses.yaml` passed twice in a row, then `.maestro/qa/ --exclude-tags ios` passed 5/5.
- `bunx tsc --noEmit`, `bun run lint` and `bun test` (37/37) are clean.
- Not run: iOS (Linux machine). iOS code paths are unchanged (`Platform.OS` branch only).

**Follow-ups.**
- Brain `decisions.md`, 2026-11-21 motion rules: record the deliberate platform difference (Android
  list rows appear without a fade) when notes are folded.
- Retry the entering fade on Android after the next Reanimated upgrade (4.7.1 now). Use the expenses
  flow's relaunch step as the check.
- The task's "appId: ${APP_ID}" wording: every flow in `.maestro/qa/` uses the literal
  `com.johnhaup.paycheckplanner` (same id on both platforms); none was changed.

**Pitfall.** An `entering` animation on a virtualized list cell can leave cells mounted after the
first batch invisible on Android (Reanimated 4.7). Maestro reports them as missing, and logcat says
"Skipping invisible child". Do not work around it with swipes, waits or `initialNumToRender`.
