# HAU-313: Income and Paychecks names wrap between words only (2026-11-13)

## What changed
- At accessibility text sizes (`useAccessibilityTextSize()`), three names now render with
  `AppWordWrapText` (the per-word text from the pay date detail) instead of a plain wrapping
  `AppText`: the source name in `IncomeSourceRow`, the source name in `PaycheckCard`'s header and
  the bill name in `PaycheckExpenseRow`. A word wider than its row shrinks alone (down to half
  size) instead of breaking at a letter ("Manufacturi / ng").
- The issue is titled for Income; it also names the two Paychecks components as wrapping "the old
  way", and they were the open follow-up of the pay date detail work, so they are in this change.
- Standard text sizes: untouched (same one-line `AppText` with "…").
- No new strings, no change to `AppWordWrapText` itself.

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean. Not run on a simulator (engineer runs have none).

## For QA
- Largest accessibility size, sample data, rename Brightline Co. to "Brightline Manufacturing and
  Logistics Holdings Co.": Income row and the Paychecks cards for that source show every word
  whole ("Manufacturing" a little smaller). On Paychecks, "Car Registration" in a card reads
  "Car" / "Registration", and a paid bill is still struck through (per word, gaps between words).
- `.maestro/qa/text-size.yaml` matches "Car Registration" on Paychecks at XXXL (`below:`), and the
  mark paid / change amount / move labels. The name is now a view labelled with the whole name
  (one accessibility element), as on the pay date detail, so the matches should hold; if the
  `below: "Car Registration"` step fails, that is this change.
- Bill with a payment link: the open icon still sits after the name; set-aside icon before it.

## Pitfalls
- Names on Expenses rows are still plain text; that screen's accessibility sizes are unchecked
  (existing AGENT_CONTEXT follow-up).
