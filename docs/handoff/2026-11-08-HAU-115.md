The mock store answers within a microtask, so it loses this race under load, and a fast real StoreKit answer could too. `refreshProEntitlement` now awaits a promise that `onRehydrateStorage` settles (on success or a failed read) before it writes. Verified: the gate's 70ab909 Release app with this branch's `main.jsbundle` swapped in (`expo export:embed --bytecode --entry-file index.ts`; a full native Release build did not finish within an hour on the loaded Mac) passed the suite 9/9 on `Paycheck Planner Dev` (16:18). Release Gate simulator not used (HAU-102).

## Lessons and pitfalls

- A zustand `persist` store rehydrates asynchronously from AsyncStorage and merges the stored state over the current one (`{...current, ...persisted}`), so any `set` made before rehydration finishes is silently overwritten. Anything that writes a fresh answer into a persisted store at launch (entitlement checks, sync) must wait for hydration first (HAU-115, `proStoreHydrated` in `src/services/pro.ts`).
