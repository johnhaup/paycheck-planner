# HAU-854 Paychecks: collapsed header stays collapsed until the top of the list (2026-11-25)

## What changed and why
- `app/(tabs)/(paychecks)/index.tsx`, `handleScroll`: since HAU-316 the header's `collapse` followed
  every scroll delta, so any scroll back in time brought the hero and chart out again, anywhere in the
  list. Now forward scrolling still collapses it by the delta, but `collapse` is capped at
  `pastTitle / collapseDistance`: scrolling back leaves it collapsed until the content above the
  header runs out, so it only comes out at the top of the list (same as the large title). From the
  top of the list nothing changes. It still collapses to the pills; it never hides.
- Unchanged on purpose: every jump (launch, tab return, chart/pill tap, Today, short-paycheck line)
  still lands with the whole header out (`jumpTo` sets `collapse` 0). Scrolling back from such a
  landing keeps it out; scrolling forward collapses it. The fold reflow already set
  `collapse = pastTitle / distance`, which is consistent with the new cap.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Runner 1 (iPhone 17 Pro, iOS 27.0), dev build on Metro, sample data, free, scratch Maestro flow in
  Dark and Light: two swipes up → pills pinned, "· left over" gone; a short swipe down mid-list →
  still collapsed (the bug); swipes down to the top → large title, hero and chart back.
- `.maestro/qa/paychecks.yaml` on Runner 1 (dev build): passed, including the large-title collapse steps.

## Not verified
- Android (same JS path, no large title; pinTop 0) and iPhone Duo not run.

## Pitfall
- Maestro `takeScreenshot` rejects absolute paths outside its output folder; use a bare name and
  read it from `~/.maestro/tests/<run>/`.
