# HAU-880: swiped-open rows close like an iOS list

**What changed**
- `src/components/AppSwipeActions.tsx`: a module-level `openRow` (the ref of the one row open or opening,
  app wide). A row claims it on `onSwipeableOpenStartDrag` / `onSwipeableWillOpen`, which first closes
  the previous row with `close()` (the same spring as a manual close), so the old row starts closing as
  soon as the new drag begins. `onSwipeableClose` and unmount release it. `useFocusEffect` cleanup
  closes the row when its screen loses focus (tab switch, a form or sheet over it).
- Exported `closeOpenSwipeRow()`; lists call it when a drag starts: Expenses and Income
  (`onScrollBeginDrag`), Paychecks (`scheduleOnRN` in the animated handler's `onBeginDrag`).
- Expenses: filter, sort and search close the open row before `useListSwap` swaps the rows, so a row
  does not come back open in the new results.
- Action buttons and haptics unchanged. No new strings, no new dependency.

**Verified** (Runner 1, iOS 27 dev build, sample data, scratch Maestro flows)
- Expenses (Dark): Savings open, then Internet swiped → only Internet open; scroll → closed;
  open, Income → Expenses → closed; open, tap another row (form) and close it → closed; open, tap
  Recurring → closed. Light: same two-row check.
- Income: Brightline open, list drag → closed. Paychecks (Light): Internet open (Move), Savings swiped
  right → Internet closed; list scroll → closed.
- `.maestro/qa/` 6/6 passed on the dev build. tsc and lint clean.

**Not verified**: a frame-by-frame recording of the hand-over (screenshots only); Android
(same JS path, gesture-handler's Swipeable callbacks are cross-platform).

**Pitfall**: keep the ref object, not `ref.current`, in `openRow`: in effect cleanups on unmount
`current` is already null.
