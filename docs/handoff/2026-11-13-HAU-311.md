# HAU-311: amount sheets, the hint no longer runs behind the buttons (2026-11-13)

## What changed
- `src/components/AmountSheet.tsx`: one empty `<View collapsable={false} />` ahead of the
  `ScrollView`, plus a comment saying why.
- Cause: not the flex layout. Yoga already shrinks the scroll area to what the pinned buttons
  leave (`maxHeight` on the body, buttons do not shrink). On iOS react-native-screens 4.30
  overrides that frame: for every `formSheet` it walks down the chain of first subviews, and the
  first `RCTScrollViewComponentView` it meets gets the whole sheet's frame, re-applied on every
  bounds change (`RNSScreen.mm`, `applyFrameCorrectionForDescendantScrollView` →
  `tryFindDescendantScrollView`, "Fallback 1"). Our ScrollView was the body's first child, so it
  was stretched over the full sheet and the buttons were drawn on top of it. With one opaque Save
  button the text happened to end above it; with two, the hint sat behind Save and showed through
  the transparent outline button.
- Fix: the empty view is now the first subview, the search ends there (it has no children), and
  the scroll view keeps the frame the layout gives it. The library has no prop for this (its own
  TODO says one may be needed).

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean.
- NOT run on a simulator: no Release `.app` to reuse on this machine (`/tmp/qa-b302` is gone, no
  DerivedData build), no `Paycheck Planner Dev` simulator, load average 440. The cause was found
  by reading the library source, so the screenshots are the proof still owed.

## For QA
- Pro (mock store), largest text size, pay date detail → pay amount → save 2100 → reopen: the
  hint stops above Save, nothing shows through "Use usual amount", scrolling never moves the
  amount field behind a button. Same on Car Registration with a custom amount.
- One-button sheets and the default text size: the scroll view used to be stretched there too
  (unnoticed), so compare the title's top and side padding with the other sheets (move bill).
- `.maestro/qa/amount-sheets.yaml`'s header comment still calls this a known defect; the
  `amount-sheets-pay-custom` / `-bill-custom` screenshots should now be clean.

## Pitfall
- In a `formSheet`, a ScrollView that is the first child of the first child (…) of the screen is
  resized by react-native-screens to the whole sheet. If it must share the sheet with pinned
  content, put a non-collapsable view ahead of it (or make the ScrollView the sheet's only content).
