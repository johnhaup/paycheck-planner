# HAU-903: Paychecks is current when its tab comes back

## What changed and why
- `useFocusedStore` (HAU-699) held store values whenever Paychecks was not focused, which includes sitting on a
  hidden tab. A change on Expenses or Income then reached Paychecks only after the tab was back on screen: about
  1.9 s of old cards in the dev build, then the whole list snapped, and the hero jumped in two or three steps.
- The hold now applies only while a screen is pushed over Paychecks (pay date, settings, any root-stack route over
  the tabs). On a hidden tab the selector reads the store as usual, so Paychecks re-renders in the background and
  `useCountUp` snaps its numbers there (it already snaps when not focused). The tab returns with current data.
- `isOnHiddenTab` walks up to the first navigator whose state `type` is `"tab"` and compares its selected route's
  nested state key with the screen's own navigator key.
- Pitfall: the check must run inside the store selector, not at render. Native tabs switch with `dispatchSync`,
  and the blur re-render happens while `getParent().getState()` still names the old tab (index 0), so a render-time
  check held the values on every tab switch. When the store changes later, the state is current.

## Verified (Runner 1, dev build on Metro, recorded and read frame by frame)
- Sample data → Expenses → swipe-delete Groceries → Paychecks: hero `$1,490.15`, Brightline Nov 27 card without
  Groceries, `1 of 4 paid`, from the first frame of the tab transition. No content changes after it (dark and light).
  (Today's sample dates give different numbers from the issue's `2 of 3 paid`.)
- Mock-store Pro → Income → add "Side Gig" weekly $500 → Paychecks: the Side Gig card is at the top from the first
  frame of the transition; nothing appears later.
- HAU-699 unchanged: on the pay date screen a temporary log showed the hold on (`hold true` for every store change),
  and removing Car Registration counted $883.00 → $948.97 → $992.37 → $1,021.32 → $1,038.71 → $1,047.49 → $1,050.61
  → $1,051.00 at 20 fps (~350 ms).
- `bunx tsc --noEmit`, `bun run lint` clean. No unit test setup in the repo. Core Maestro suite not run (no flow
  touches this; the gate runs it).
