# HAU-770: persistence moves from AsyncStorage to expo-sqlite

**What changed.** The five zustand stores stay the in-memory model (no screen changed); `persist` on AsyncStorage is gone and `@react-native-async-storage/async-storage` is out of `package.json`.
- `src/db/migrations.ts`: tables `income_sources`, `expenses`, `assignments`, `paycheck_overrides` (each `id`, `created_at`, `updated_at` ms, `deleted_at` tombstone, no foreign keys) and `settings` (one row per field: `themeMode`, `hideCents`, `reminders.*`, `language`, `currency`, `pro`, plus `legacyImportedAt`). An override's id is `sourceId|payDate`.
- `src/db/budget.ts`: `loadBudget` (live rows, `ORDER BY created_at, rowid`) and `saveBudgetChanges(prev, next)`, which diffs each store change into upserts and tombstones. Never `DELETE`; a row that comes back (Undo, restore, sample data after Erase) loses its tombstone and keeps `created_at`. Covers every `useStore.setState` path too.
- `src/db/legacyImport.ts` + `legacyAsyncStorage.ts`: on first launch reads the old store once (iOS: `Library/Application Support/<bundle>/RCTAsyncLocalStorage_V1`, `manifest.json` plus md5-named files; Android: `databases/RKStorage`), `INSERT OR IGNORE`s it, writes `legacyImportedAt`. A failed read writes nothing and retries next launch. The old files stay on disk.
- `src/db/init.ts` is `SQLiteProvider`'s module-level `onInit` (migrate, import, load the stores, then subscribe writers). `app/_layout.tsx` wraps the old root (now `RootNavigator`) in the provider and holds the splash until it has loaded.
- `localeStore`: the AsyncStorage wait before an RTL reload is gone (the settings row is written synchronously in the subscriber); `syncLayoutDirection` replaces `persist.onFinishHydration`.
- `rescheduleExpense` gives the re-appended assignment a new id, so it sorts last after a relaunch as in memory.
- Tests: `bun test` (new `test` script, `@types/bun`, `"types": ["bun"]`). `src/db/testDatabase.ts` runs the real SQL on `bun:sqlite`. The fixture `src/db/__fixtures__/RCTAsyncLocalStorage_V1/` was captured from `main` @ 0624fd1 on the simulator (sample data, Pro, 2 overrides, paid marks, a bill amount, a moved bill's skip marker, Light, Hide cents, Spanish, reminder 2 days before).

**Verified (iOS sim, Runner 1).** Captured that store on `main`'s build, then `runner devapp` and launched over it: every bill, source, paid mark, the $200 bill amount, both overrides, Light, Spanish, Hide cents, reminder and Pro came through; all five tables had rows. Deleted a bill: bill and its assignment kept with `deleted_at`. Deleted an income source and tapped Undo: `deleted_at` back to NULL. Cold relaunch: the bill stays gone, counts unchanged, `legacyImportedAt` unchanged. `settings.yaml`'s Erase all data leaves every row as a tombstone. Fresh install opens Dark and empty; Arabic reloads once into RTL and stays RTL after a cold start. `bunx tsc --noEmit`, `bun run lint`, `bun test` (12 pass), Maestro `.maestro/qa/` 6/6.

**Not verified.** Android: the `RKStorage` import has never run (the Android regression run after the merge covers the suite, not the upgrade). Note: a launch without `-proStoreMock` re-asks the real store and writes `pro = false`, as before.

**Pitfalls / follow-ups.**
- QA tricks in the brain's `qa.md` that `sed` the AsyncStorage file no longer work: terminate the app and edit `<data container>/Documents/SQLite/paycheck-planner.db` with `sqlite3` (e.g. `UPDATE income_sources SET first_pay_date = '2026-07-03'`). Deleting `Documents/SQLite` re-runs the import from the old files, which is a quick way to retest the upgrade.
