# HAU-538: Income Source and Expense forms get a Close button

## What changed and why
- `app/_layout.tsx`: `incomeFormOptions` and `expenseFormOptions` now set
  `headerRight: renderCloseButton`, the same X (Ionicons `close`, label `common.close`,
  `router.back()`) Settings and the paywall use. Daily visual QA found both forms had no visible
  way out besides the swipe-down, which nothing on screen suggests.
- Picked the X over an iOS-style "Cancel" on the left: one dismiss pattern across all modals,
  no new string, and an icon button needs none of the width/padding care a text `headerRight`
  needs (HAU-326, HAU-537). Close discards unsaved edits without asking, as swipe-down already did.
- Swipe-down is unchanged (no `gestureEnabled` change).

## Verification
- `bunx tsc --noEmit`, `bun run lint`: clean.
- Release build on Paycheck Planner QA 27 (iOS 27.0), Dark: `.maestro/qa/income.yaml` and
  `expenses.yaml` pass (2/2), including the paywall-over-expense-form "Close" step.
- Scratch flow (not committed): Income form with a typed name → Close → back on Welcome, nothing
  saved; Expense form (sample data) → Close → form gone. Screenshots show the X at top right of both.
- Not checked: Light mode, accessibility text sizes, RTL, Android (same shared button as Settings).

## Pitfall
- `expenses.yaml` opens the paywall on top of the expense form (Set-aside segment) and taps
  "Close". Both modals now have a "Close" button; Maestro still hits the paywall's (topmost).
