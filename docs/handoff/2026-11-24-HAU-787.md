# HAU-787: iCloud sync of the budget (iOS)

**What changed.** `@johnhaup/expo-cloud-sync` pinned to `github:johnhaup/expo-cloud-sync#v0.4.0`, iOS only at runtime.
- `app.json`: the module's plugin (container `iCloud.com.johnhaup.paycheckplanner`, `backupInclude` `database/RKStorage` so Android Auto Backup keeps un-imported AsyncStorage data). `plugins/withoutPushEntitlement.js` deleted: CKSyncEngine needs `aps-environment`.
- `src/db/sync.ts`: `SYNC_CONFIG` (four budget tables, then `settings` with `excludeKeys`). Synced settings: `currency`, `hideCents`, `autoMarkPaidOnLinkTap`. Device-only: `pro`, `legacyImportedAt`, `language` (RTL reload), `themeMode`, `reminders.*` (Pro, per-device permission).
- `src/db/init.ts`: `installSync` after `migrate`, before the legacy import (iOS only). `loadStores(db)` fills the stores behind a `loading` flag that the write-through subscribers skip: writing a reload back would re-stamp synced rows and bounce them between devices forever.
- `src/components/SyncedStores.tsx` reloads the stores when `useCloudSync().revision` goes up; `app/_layout.tsx` wraps the navigator in `CloudSyncProvider` on iOS.
- Restore from backup calls `stampBudget(db)` (`src/db/budget.ts`) after the store change, so rows the restore left unchanged still beat a newer copy another device has not delivered yet.
- `src/components/settings/SettingsSyncSection.tsx` above Data (iOS only): switch + hint per state, "Try again" on `error`, "Merge into this iCloud account" on `accountChanged`, "Turn off and delete iCloud copy" while a copy may exist. 21 strings under `settings.sync` in all 45 locales (non-English written by an agent, not reviewed by a native speaker).

**Verified.** `bun test` 23 pass: new `src/db/sync.test.ts` checks every schema table is in the config, every settings key is synced or device-only, Pro/language/reminders never get marked dirty, and runs two devices through the module's memory cloud on the real schema (all four entity kinds arrive, the later edit wins, edits to two different bills both survive, a delete propagates, a restore beats an unfetched newer edit, Pro/theme/language stay put while currency/hideCents sync). Runner 1 (no iCloud account): the dev build's entitlements carry the container, CloudKit and `aps-environment`; Settings shows the signed-out hint. Upgrade: sample data, then dropped `_sync_*` tables and triggers (= `main`'s database), relaunched: 2/9/4 rows intact, all 15 in `_sync_changes`, 14 triggers. `-cloudSyncMock`: signed-in state with "Last synced", delete alert, switch off ("Off…", survives relaunch) and on, in Dark, Light, Arabic RTL and AccessibilityXXXL. tsc, lint, `.maestro/qa/` 6/6 on the dev build.

**Not verified.** Real CloudKit between two simulators: the job's simulator has no iCloud account, so live two-device sync, push and `accountChanged` are untested in this app (the module's CloudKit test on one simulator passed). Android unchanged by design (no provider, no section).

**Pitfalls / follow-ups.**
- With `-cloudSyncMock`, "delete iCloud copy" leaves sync on: the mock runs the Android cycle, whose `signOut` does not set `enabled = 0`. The real iOS engine does. Module issue, not this app's.
- John: after the first dev build on an iCloud-signed simulator saves a record, CloudKit Console → Deploy Schema Changes to Production, or TestFlight builds cannot save. The App Store profile already has iCloud and push (regenerated 2026-11-24).
- Accepted: Erase all data erases on every synced device (Undo works); sample data's fixed `demo-*` ids can merge into a real budget on a new device; a free user can end up with two income sources from two devices; concurrent delete-source/add-bill can leave a dangling `income_source_id`.
- Migrations on synced tables are additive only from now on; never `DELETE` from them (the trigger aborts it).
- QA: Settings gains a Sync section; `settings.yaml` can add steps with `-cloudSyncMock`. Link rows' accessibility label ends in ", " (use a regex in Maestro).
