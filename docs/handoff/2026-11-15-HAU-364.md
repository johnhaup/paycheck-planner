# HAU-364: Japanese date tile wraps "20日" (2026-11-15)

## Changed
- `src/utils/dates.ts`: new `formatDayNumber(date)`, the day formatter's output with every
  non-digit (`\P{Nd}`) removed, falling back to `String(date.getDate())`. ja, zh-Hans, zh-Hant
  ("20日") and ko ("20일") now give "20"; locales with native digits keep them (bn "২০").
- `src/components/AppDateTile.tsx` (Paychecks cards and the pay date detail) shows
  `formatDayNumber` instead of `formatDayOfMonth`. The month ("11月") is already above it, so
  the number alone reads as a calendar tile does in Japanese. Tile size unchanged.
- `formatDayOfMonth` stays for the pay schedule descriptions in `payDates.ts`, where the
  suffix belongs in the sentence.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- `Paycheck Planner Dev` (iOS 27, dark, default text size), Release app with this branch's
  `export:embed` bundle, sample data, app language 日本語: Paychecks tiles "11月 / 30",
  "12月 / 4" on one line each; pay date detail tile "11月 / 30". Language set back to English
  and the original bundle restored afterwards.
- Node ICU check of the string for en, ja, zh, ko, ar, ar-EG, he, ur, bn, hi, mr, th, de, ru.
- Not run: `.maestro/qa/`, Korean and Chinese on the simulator, accessibility text sizes.

## Lesson
- Hermes on iOS has no `formatToParts`, but `\p{Nd}` regexes work, so strip to digits
  instead of picking the `day` part.
- `-AppleLanguages "(ja)"` does nothing on a simulator whose app has a saved language; pick
  it in Settings → Language.
