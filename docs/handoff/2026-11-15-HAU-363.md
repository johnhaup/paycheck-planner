# HAU-363: Expenses group header and rows stack at accessibility sizes (2026-11-15)

## What changed
- `AppSectionHeader`: at accessibility text sizes (`useAccessibilityTextSize()`) the title and the
  trailing value stack (title first, value below), and the title renders with `AppWordWrapText`, so
  "BRIGHTLINE CO." wraps between words only. Standard sizes are unchanged. The component is
  shared, so the same stacking applies to the section headers on Paychecks (month + count), the
  pay date detail, Income and Settings.
- `AppWordWrapText` accepts the `section` variant (uppercase per word, from the variant).
- `ExpenseRow`: also stacks at accessibility sizes, like `IncomeSourceRow` does: tile, then
  the payee (`AppWordWrapText`, set-aside icon and link icon kept), then meta and goal lines
  (no longer cut to one line), then the amount (one line, shrinks down to half size) and the cadence.
  The issue asked for the rest of the screen to be checked too, and this was the AGENT_CONTEXT
  follow-up "Accessibility text sizes on Expenses are unchecked".
- No new strings.

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean.
- Release build on `Paycheck Planner Dev` (iOS 27), sample data, scratch flow: at Accessibility
  XXXL every header reads whole ("BRIGHTLINE" / "CO.", "MESA HEALTH", "ONE-TIME") with its total
  below, and every row stacks with whole words ("Car" / "Registration"). Default size: identical
  to before. `.maestro/qa/` expenses, paychecks, settings, income: all pass on that build.

## For QA
- Expenses at Accessibility XXXL with sample data: "BRIGHTLINE CO." / "MESA HEALTH" headers read
  whole, "$1,477.33/mo" below them; rows stack with whole words. Default size looks as before.
- No flow changes needed; the four affected journey flows pass.

## Pitfalls
- At XXXL a payee that wraps to two lines pushes its link icon to the row's right edge (the word
  row takes the full width once it wraps), the same as on Paychecks since HAU-313. Cosmetic.
- A fresh worktree has no `node_modules`; `bunx tsc` then fetches a bare tsc and reports
  hundreds of bogus errors. Run `bun install` first.
- A cold Release build (`prebuild` + pods + `xcodebuild`) takes more than 10 minutes; give the
  background command a longer timeout.
