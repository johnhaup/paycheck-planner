# HAU-806: iCloud sync on expo-cloud-sync v0.4.1

## What changed and why
- `package.json` pins `github:johnhaup/expo-cloud-sync#v0.4.1`; `bun.lock` resolves it to `#ea88026` (was `#4708cf4`). Only the pin, the resolved commit and its integrity hash moved.
- v0.4.0 let a reinstall or a new device push its default settings over the iCloud copy. v0.4.1 sets `fresh` in `_sync_meta` when no `device_id` is stored; until the first successful fetch clears it, remote rows win (`decide(local, remote, fresh)`). Module note: `~/Projects/expo-cloud-sync/docs/handoff/2026-11-24-HAU-792-fresh-install.md`.
- No app code changes: `installSync`, `useCloudSync` and `CloudSyncProvider` are unchanged.
- New test in `src/db/sync.test.ts` ("a new install that changes settings before its first sync takes the iCloud settings"): device C writes a newer `currency` before its first sync and ends on iCloud's EUR; its `hideCents`, a key iCloud lacked, still goes up.
- Existing tests needed no `device_id` seeding: each device's first `runCycle` pulls and ends the fresh state before any conflicting edit.

## Native
- The module's Swift (`CloudSyncEngine.swift`) changed: this needs a new build, not an OTA update. Dev client rebuilt with `runner devapp`.

## Verified
- `bun test` 38 pass, `bunx tsc --noEmit` clean, `bun run lint` clean.
- Dev build on Runner 1, cleared state: `_sync_meta` held `fresh|1` and a `device_id`. Relaunched with `-cloudSyncMock YES`: Settings > Sync showed "Last synced", and `fresh` was gone (`device_id`, `account_id`, `cursor`, `last_synced_at` left), so v0.4.1 is in the build.
- Signed out of iCloud: the Sync switch is off and disabled with its hint (Dark).
- `.maestro/qa/` on the dev build: 6/6 passed.

## Not verified
- A real iCloud reinstall adopting existing settings: the simulator is not signed in to iCloud. Covered by the new test and the module's own reinstall check on Plate Weight (HAU-792).
- Android: not rebuilt; `installSync` is iOS-only (`src/db/init.ts`). Type check and tests only.

## Trade-off (accepted in the module)
- An install that never synced and is used offline loses same-key settings rows to the iCloud copy on its first fetch; its new rows are kept. TestFlight installs upgrading from v0.4.0 already have a `device_id`, so they are not treated as fresh.
