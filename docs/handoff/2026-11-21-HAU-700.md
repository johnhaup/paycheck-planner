# HAU-700 Add expense: error toast covers the sheet title and close button

## What changed and why
- sonner-native draws its toasts at the top of the window, over a modal sheet's header, so a refused
  save hid the sheet's title and X.
- `AppInput` takes an optional `error`: the field gets a 1pt `destructive` outline and the message sits
  under it as a red `caption` (`accessibilityRole="alert"`, polite live region). With no `error` it
  renders the same as before. It also takes `ref` (React 19 ref-as-prop, `TextInputInstance`).
- `app/expense-form.tsx`: all four refusals (payee/name, amount, goal, due day) go to the field
  instead of `toastError`. The form keeps the warning haptic, focuses the invalid field (the
  KeyboardAwareScrollView brings it into view), and clears the error when the user edits that field.
  No new strings; the existing messages are reused.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Scratch Maestro flow on Runner 1 (dev build, Metro 8082): an empty payee shows the red outline and
  "Payee name is required." with the header and X visible; typing clears it; then an empty amount
  shows "Enter a valid amount." on the focused amount field. Screenshots in dark and light mode.
- `.maestro/qa/expenses.yaml` passes.

## Follow-ups
- The same top toast is used by the income form (`app/income-form.tsx`), the amount sheets
  (`paycheck-amount`, `expense-amount`) and the one-time bill (`OneTimeExpenseForm`). Each can move
  to `AppInput`'s `error` the same way if the design review flags them.

## Pitfalls
- Maestro's `takeScreenshot` refuses absolute paths outside its output folder; pass
  `--test-output-dir` and use a bare name.
