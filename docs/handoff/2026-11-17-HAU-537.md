# HAU-537: Mark all paid has side padding inside its header pill (2026-11-17)

## What changed
- `app/pay-date-detail.tsx`: the `headerRight` Pressable gets `paddingHorizontal: 12`
  (`MEASUREMENTS.spacing.base`, `styles.headerButton`, wrapped by `dimOnPress` as
  `HEADER_BUTTON_STYLE`). iOS 26+ wraps a custom bar button in a glass pill that hugs its
  content, so the bare `AppText` ran edge to edge; Back has ~17 pt between its text and the pill
  edge, the button now has the same (12 pt padding + the pill's own ~5 pt).
- HAU-326/HAU-303 behaviour kept: text one line, max 40% of the window width, shrink to 0.7,
  `maxFontSizeMultiplier` 1. The padding sits outside the text's cap, so the pill is up to
  40% + 24 pt wide.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- `Paycheck Planner QA 27` (iOS 27.0), installed Release build with this branch's
  `export:embed` bundle copied over `main.jsbundle`, sample data, the Nov 20 Brightline paycheck.
  Header screenshots read: Dark and Light at default size, Light at AccessibilityXXXL (en): text
  to pill edge ≈ 50 px each side, Back's ≈ 51 px. ml (longest translation): button text whole,
  "Pay Date" title whole, Back is a chevron as before. Tapping Mark all paid marked all five
  bills and showed the Undo toast.
- `.maestro/qa/paychecks.yaml` passed on that build. No flow edited.
- Not checked: Android (the padding applies there too; Material headers draw no pill), RTL.

## Pitfall
- A text `headerRight` needs its own horizontal padding on iOS 26+; UIKit's glass pill adds only
  a few points. Icon buttons look fine without it because the pill has a minimum width.
