# HAU-867 Paychecks: tapped jumps fade instead of scrolling (2026-11-26)

## What changed and why
- `app/(tabs)/(paychecks)/index.tsx`: every tapped jump (chart column or pill, Go to this month, the
  short paycheck line, the selected-pill tap from HAU-630) fades the list out (90 ms), jumps without
  animation while hidden, as the opening jump does, and fades back in (180 ms, `FADE`). The UIKit
  animated scroll and its `settle` repeat are gone. A drag or status-bar tap while hidden shows it.
- Cause: during a programmatic scroll the pinned header's Reanimated transform does not reach the
  screen until the scroll stops (worklet logs had `pinShift` right every frame; the recording had
  the header riding with the rows). The large title expanding on the way up cut UIKit's scroll short:
  the 0.4 s still frame and snap.
- QA round 1 (blank of 1.4-2.3 s): the list had no `strictMode`, so FlatList wrapped `renderItem`
  anew on every render and every month change (and VirtualizedList's own window updates) re-rendered
  all ~70 mounted rows: ~0.75 s per render on the dev build, 2-3 per tap. The landing waits for the
  JS thread, so the list stayed blank. Main paid the same cost; UIKit's scroll hid it. With
  `strictMode` a month change renders in ~30 ms.

## Tried and ruled out
- Scrolling from a UI-thread worklet each frame, and a flight with no React render: header still froze.
- Reanimated's `IOS_SYNCHRONOUSLY_UPDATE_UI_PROPS` flag: native, app-wide, and the runner's dev-build
  fingerprint does not hash `package.json` `reanimated.staticFeatureFlags`, so it could not be tested.

## Verified (Runner 1, iPhone 17 Pro, iOS 27.0, dev build on Metro, sample data, Pro mock)
- tsc and lint clean. smoke, paychecks, pro pass.
- Two recordings of 3 x (Feb, Go to this month), per-frame brightness (brain `qa.md` recipe): Feb
  blanks 0.25-0.28 s, Go to this month 0.19-0.20 s, every time, each fading in; no frame has the
  header mid-list. Light mode: rows re-theme with the memoized renderer.

## Not verified
- Android (same JS; no large title), iPhone Duo, Release timing, Reduce Motion (fades use
  `ReduceMotion.Never`, as everywhere in the app).

## Follow-ups and pitfalls
- The header shows the new month (label, hero count-up) during the 90 ms fade-out (QA non-blocking).
- Timing JS on a dev build: `console.log` reaches neither `simctl log stream` nor the agent; a scratch
  `fetch` POST to a local HTTP server plus React `Profiler` worked.
