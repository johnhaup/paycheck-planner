# HAU-867 Paychecks: tapped jumps fade instead of scrolling (2026-11-26)

## What changed and why
- `app/(tabs)/(paychecks)/index.tsx`: every tapped jump (a chart column or pill, Go to this month,
  the short paycheck line) now fades the list out (90 ms), jumps without animation while it is
  hidden, the same way the opening jump does, and fades it back in (180 ms, `FADE`) once the offset
  holds. That takes about 0.3 s, the same every time. The UIKit animated scroll and its `settle`
  repeat are gone.
- Cause: during any programmatic scroll the pinned header's Reanimated transform does not reach the
  screen until the scroll stops. Worklet logs showed `pinShift` correct every frame while the
  recording showed the header riding along with the rows (mid-list, bill rows above the hero). The
  large title expanding on the way to the top also cut UIKit's animation short, which caused the
  0.4 s still frame and the snap.
- A drag or a status-bar tap while the list is hidden now shows it again (`hidden` false), since
  nothing else would once the jump has ended.

## Tried and ruled out
- Driving the scroll from a UI-thread worklet (`scrollTo` each frame from a `withTiming`, with the
  pin set from the same value): the header still froze. So did a test with no React render during
  the flight (count-up off, flight started after the commit), so React commits are not the cause.
- Reanimated's `IOS_SYNCHRONOUSLY_UPDATE_UI_PROPS` static flag might fix the transform, but it is
  native, app-wide, and lives in `package.json` `reanimated.staticFeatureFlags`, which the runner's
  dev-build fingerprint does not hash (only `packageJson:scripts`), so a dev build would not pick it up.

## Verified (Runner 1, iPhone 17 Pro, iOS 27.0, dev build on Metro, sample data)
- `bunx tsc --noEmit` and `bun run lint` are clean.
- Pro on the mock store, Feb tap then Go to this month, three times per recording (`simctl io
  recordVideo`, every frame tiled), four recordings: no frame shows a bill row above the hero or the
  hero over rows. Each jump is fade, blank, fade in, landing on Feb or the top of November. The first
  tap after a launch has the longest blank (about 0.45 s, dev build); later ones about 0.1 s.
- Light, free tier: Dec then Go to this month, the same.
- `.maestro/qa/paychecks.yaml` and `pro.yaml` pass on Runner 1.

## Not verified
- Android (same JS; pinTop 0, no large title), iPhone Duo, Release timing, Reduce Motion (the fades
  use `ReduceMotion.Never` on purpose: fades stay under Reduce Motion, as everywhere in the app).

## Pitfall
- The selected-pill tap (HAU-630) also scrolled programmatically and had the same header drift. It
  now fades as well.
