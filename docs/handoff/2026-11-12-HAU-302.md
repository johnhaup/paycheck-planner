# HAU-302: pay date detail names wrap between words only (2026-11-12)

## What changed
- New `AppWordWrapText` (`src/components/AppWordWrapText.tsx`): lays a name out word by word in a
  wrapping row. Each word is a one-line text with `adjustsFontSizeToFit` (minimum scale 0.5), so
  a word wider than the row shrinks to the row's width and every other word keeps its full size.
- Used only at accessibility text sizes (`useAccessibilityTextSize()`), for the bill name in
  `PayDateExpenseRow` and the source name in `PayDateSummary`. Standard sizes are untouched.
- Why not `adjustsFontSizeToFit` on the whole name: React Native's fit check
  (`NSTextStorage+FontScaling.m`) only looks for truncation and height, so a word broken at a
  letter counts as fitting and nothing shrinks. Moving the remove icon to its own line would not
  help the header, where "Manufacturing" is wider than the whole screen at the largest size.
- Names in scripts written without spaces (CJK, Thai, Khmer, …) keep the plain wrapping text.
- The word row takes the direction of the name's script, not the layout's, so an English name in
  an Arabic layout does not read backwards; it is one accessibility element labelled with the name.

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean. Not run on a simulator (engineer runs have none).

## For QA
- Largest accessibility size, sample data, first paycheck: "Car Registration" reads "Car" /
  "Registration" (second word slightly smaller, whole); a source renamed "Brightline Manufacturing
  and Logistics Holdings Co." shows every word whole. A paid bill is still struck through
  (per word). Default size unchanged. Worth one look in Arabic with an English bill name.

## Follow-ups / pitfalls
- A word that still does not fit at half size ends in "…" instead of breaking.
- `PaycheckExpenseRow` and `PaycheckCard` on Paychecks wrap names with a plain text at
  accessibility sizes and can break a long word the same way; `AppWordWrapText` is the tool.
