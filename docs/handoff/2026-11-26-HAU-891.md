# HAU-891: new-expense form hopped up and back when the keyboard closed

**What changed**
- `app/expense-form.tsx`: `KeyboardAwareScrollView` gets `mode="layout"`.

**Why**
In the default `insets` mode the keyboard height is a native contentInset on the scroll view. With
`contentInsetAdjustmentBehavior="automatic"` (HAU-716, content under the transparent title bar) and
content shorter than the sheet, closing the keyboard reset the offset to 0 instead of the
-inset rest position: the form sat ~40 pt too high for ~13 frames, then snapped back. `layout` mode
grows a spacer view instead of touching insets, so the offset is never reset.

**Ruled out**
- `disableScrollOnKeyboardHide`: no change.
- Dropping `contentInsetAdjustmentBehavior`: removes the jump but the form then rests under the bar
  (undoes HAU-716).

**Verified** (Runner 1, iOS 27 dev build; `simctl io recordVideo` + Maestro taps, frames at 20 fps,
frame-difference of the top 30% of the screen)
- Before: spikes at keyboard close (~13 frames shifted). After: none, for Return on Payee and for
  closing the number pad after typing an amount; form position identical before and after.
- `bunx tsc --noEmit`, `bun run lint` clean.

**Edit form** (existing bill, Rent from sample data; it scrolls): recorded Return on Payee and number pad
close on Runner 1; top-30% frame diffs stay ~0 through the close, field positions identical in the
frame strips. Tap Rent by point (`26%,74%`): matching the text "Rent" finds nothing in Maestro.

**Not verified**
- Income form (code untouched) and Android.

**Pitfall**
`takeScreenshot` in Maestro only accepts paths inside its output folder; use `simctl io screenshot`.
