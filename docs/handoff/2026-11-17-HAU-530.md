# HAU-530: Android build failed @ b67c690 (submit)

## What happened

The Android run of `main` @ `b67c690` (`builds-android/paycheck-planner/2026-11-17-100556` on the
Linux worker) passed the gate (5/5 flows, `report.xml` has 0 failures), built and signed the AAB
(version code 7), uploaded it to EAS Submit and scheduled the submission at about 10:18. `eas submit`
then waited for the result and, 40 minutes later (10:58, the log's mtime), exited with
`request to https://api.expo.dev/graphql failed ... GraphQL request failed`: the status polling
lost its connection to Expo. The submission itself had gone through; nothing in the app, the
flows or `eas.json` is broken.

## What changed

Docs only. The follow-up in `docs/AGENT_CONTEXT.md` that said the first `eas submit` through the
runner had not happened yet is no longer true; it now says it has, and names this failure mode.

## How it was verified

Play Developer API with the app's service account key (a throwaway edit, read and deleted again;
nothing changed in Play):
- Internal track: release `1.1.0`, version code 7, status `draft`, next to John's hand-uploaded 3.
- Play's bundle list has version code 7 with sha256 `39f46d69…c6398cc6`, the same as
  `sha256sum` of the run's `app.aab`. So the bundle in Play is this run's build.

Not checked: the submission page on expo.dev. No code change, so `tsc` and lint are unaffected.

## Lessons

- A `submit` failure whose last lines are "Scheduled Android submission … Submitting … GraphQL
  request failed" is a polling failure, not a rejection. Look at the internal track (script idea in
  the HAU-496 note: `edits.insert`, `edits.tracks.list`, `edits.bundles.list`, `edits.delete`).
- Releases arrive as `draft` (`releaseStatus: draft`); testers get them only after John rolls
  the draft out in Play Console. The next run's draft replaces this one.

## Follow-ups

- linear-runner (not this repo): after a non-zero `eas submit`, ask Play whether the version code is
  on the track (or run `eas submit --no-wait`) before filing a ticket and holding Android builds.
