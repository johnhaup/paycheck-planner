# HAU-904: amount sheets select the old amount on open (2026-11-26)

## What changed
- `src/components/AmountSheet.tsx` (body of the bill and pay amount sheets): the input's
  `onFocus` selects the whole amount one frame later through the ref
  (`requestAnimationFrame` + `setSelection(0, amount.length)`). `selectTextOnFocus` is gone:
  it did nothing here and the new handler covers every focus, including a tap back into the field.
- Cause: with `autoFocus` inside a `formSheet`, iOS 27 puts the caret after the old amount
  and RN's `selectTextOnFocus` never selects, so number-pad digits were appended (70 -> 7085).

## Verified (Runner 1, iOS 27.0, dev build on Metro, Pro on the mock store, sample data)
- Before the fix, scratch Maestro flow tapping the real keys (`tapOn: "8"`, `tapOn: "5"`) on
  Internet ($70): field read `7085` (reproduced).
- After: Internet sheet opens with `70` highlighted, 8, 5 -> `85`, Save sets assigned +$15;
  Brightline pay sheet opens with `1980` highlighted, 8, 5 -> `85`. Dark and light.
- `bunx tsc --noEmit`, `bun run lint` clean.

## Not verified
- Android (setSelection is cross-platform; no emulator on this Mac). Large text sizes (layout
  untouched).

## Pitfall
- `selectTextOnFocus` is unreliable for an autofocused input in a form sheet on iOS 27; select
  from `onFocus` a frame later instead. `.maestro/qa/pro.yaml` still uses `eraseText` +
  `inputText`; both still work with the selection.
