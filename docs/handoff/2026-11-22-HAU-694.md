# HAU-694: Duo store screenshots in every store locale

- `bun store:screenshots:duo` now captures once per app language and frames every store locale with captions
  (en-US plus the 49 listings) from its own language's capture. Before, one English capture was framed for all.
- Language: the app is launched with `-AppleLanguages (<lang>)` (Maestro for the folded cover, `simctl launch`
  for the unfolded inner screen). Store locale → app language as iOS picks it: exact file (`pt-BR`, `zh-Hans`)
  else the base (`de-DE` → `de`). en-US/en-GB/en-AU/en-CA share one capture, as do es-ES/es-MX, fr-FR/fr-CA.
- Labels: `ship/screenshots.yaml` takes every tapped or awaited label from an env var with the English text as
  default (the iPhone set's `expo-local-ship screenshots` passes none, so it is unchanged). The Duo script builds
  each language's values from `src/localization/locales/<lang>.json` (placeholders become `.*`, the rest escaped).
  The paycheck card is matched by `<comma> Brightline Co.<comma>` with the language's comma (`,` `،` `、`).
  duoctl labels are matched after stripping bidi marks. In RTL the sidebar button and the list column are on the
  right, so those x positions are mirrored.
- Sample budget: "Emergency fund", "Vacation", "Car repair" were English-only literals in `buildStoreDemoData`;
  now `demo.emergencyFund|vacation|carRepair` in all 45 locales (store-demo builds only, so users never see them).
- Amounts stay US$ (region untouched): the sample budget is dollar-sized; a JPY or INR listing with ¥1,980
  paychecks would look broken.
- Files: English stays in `raw/` and `unfolded/landscape/`, other languages in `raw/<lang>/` (gitignored, like
  non-en-US frames already were). Landscape is English only (not uploaded, framer is portrait only).
- `openTab` finds the sidebar button in the nav bar (RTL puts it beside the status bar) and retries a dropped tap.
- Shots are staged outside the project until the run ends: Metro saw each PNG and put "Refreshing..." on the next.

## Verified

- "Duo Runner 1" (iPhone Duo, iOS 27.1), dev build on an `EXPO_PUBLIC_STORE_DEMO=1` Metro, duoctl v0.2.1:
  en-US, de-DE, ar-SA, ja captured and framed on both screens, every image read. de/ja/ar show translated
  captions, app UI and sample names; ar is mirrored. en-US regenerated and compared with the committed set: same.
  en-AU/en-CA/en-GB framed from the English capture. The other 43 store locales ran after the PR opened (see PR).
- Standard iPhone (`Runner 1`, iOS 27.0): `ship/screenshots.yaml` with no env (the iPhone set's path) took all
  7 shots in English, as before.
- `bunx tsc --noEmit`, `bun run lint` clean.
- Seen, not fixed (app layout, not this ticket): unfolded Duo, the detail pane's header squeezes the source
  name and date into a thin column beside a long "Mark all paid" (de "Alle als bezahlt markieren", ja), in
  `src/components/payDateDetail/PayDateDetail.tsx`. Shows in those store shots.

## Pitfalls

- A full run is ~45 languages × 5–6 min ≈ 4 h; use `--locales=` while iterating.
- The "Open in Paycheck Planner?" alert is SpringBoard's, in the simulator's language: it stays "Open".
- Follow-up (not this ticket): no listing has captions for `move` and `goals`, so those two framed shots carry
  English captions in every locale (needs John's caption copy, as noted in HAU-660's handoff).
