# HAU-172: Arabic negative amounts keep the currency code together (2026-11-13)

## What changed
- `src/utils/money.ts`: the right-to-left mark that `formatCompactMoney` added after the number
  (HAU-154) is now one helper, `closeNumber`, and `formatMoney` and `splitMoney` use it too. When
  the formatted string carries a right-to-left mark (Arabic, Hebrew), an RLM (`‏`) goes
  after the last digit. Other languages get the identical string as before.
- Why: Arabic puts an LRM on the minus sign, which makes "-292.84 US" one left-to-right run and
  leaves "$" alone on the other side ("$-292.84 US"). The RLM ends the run at the number, so it
  reads "$US -292.84", like positive amounts and the chart.
- `splitMoney` formats through `formatMoney` and cuts afterwards, so the mark lands in the cents
  half (or in the whole half when cents are hidden). The two halves are nested text in one
  paragraph (`AppHeroAmount`, `ExpenseRow`, `IncomeSourceRow`), so display order is decided on
  the joined string and the cut does not matter.
- Every caller of `useMoneyFormat().format` / `.split` / `.whole` and `paydayReminders` gets the
  fix: hero, paycheck cards, pay date detail, expenses, history, move-bill, notifications.
- `formatMoneyIn` (currency picker) is unchanged: positive sample only. Deleted the matching
  follow-up from `docs/AGENT_CONTEXT.md`.

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean.
- CoreText script (the method in `docs/AGENT_LESSONS.md`): `NumberFormatter` output for `ar` +
  USD is `RLM LRM -292.84 NBSP US$`, the string in the issue, and draws "$-292.84 US"; with the
  mark it draws "$US -292.84". Same for -2,475,172.84, for hidden cents ("$US -293") and for
  CA$. Positive amounts, `ar_AE`, `ar_EG`, `ar_SA` (Arabic-Indic digits), Hebrew, Urdu, Persian
  and English draw exactly as before.
- Dev build on `Paycheck Planner Dev` (iOS 27.0), the issue's steps (sample data, 2560 bill on
  Brightline every paycheck), screenshots read: Arabic hero "$US -292.84", meta line and short
  warning intact, cards "$US -1,677.00" left and "short by $US 1,677.00", chart unchanged;
  Hebrew "$ -292.84" as before. English strings are untouched by construction.
