# HAU-868: Expenses Sort no longer slides the search bar out

## What changed and why
- Cause: iOS 27 on iPhone treats a tap anywhere on the navigation bar as scroll to top
  (iPadOS has done it since 26). At the top of a list whose search bar is hidden, scroll to
  top reveals the search bar, so the list moved down 45pt. The action sheet had nothing to
  do with it: a Sort button with a no-op handler, or a tap on empty bar space, did the same.
  A React view in `headerRight` (a custom view inside a UIBarButtonItem) does not stop the
  system tap recogniser.
- Fix (`app/(tabs)/expenses/index.tsx`): on iOS, Sort is a native bar button item through
  `unstable_headerRightItems` (SF Symbol `arrow.up.arrow.down`, label "Sort", tint
  `textDefault`). UIKit's own bar buttons stop the scroll to top. It still opens the same
  ActionSheetIOS. Android keeps the Pressable `headerRight` and its Alert.
- Ruled out: react-native-screens' `ScrollToTopGuard` exists for this exact problem, but it
  is a "gamma" component that is compiled out unless `RNS_GAMMA_ENABLED=1` is set at pod install,
  so using it would mean a native change. `scrollsToTop={false}` would also turn off the
  status-bar tap.

## Verified (Runner 1, iPhone 17 Pro, iOS 27.0, dev build)
- Recorded Sort → Cancel, then Sort → Name, and sampled the video at 20 fps. The top edge of the filter control
  stays at y = 128pt in every frame (the search bar out would put it at about 173pt).
- Pull down still reveals "Search bills"; typing "Rent" shows Rent only. Light and dark mode
  look right. The empty state still shows no Sort button.
- `.maestro/qa/expenses.yaml`: every step through Sort and the filters passes. The flow fails
  later at `Due the 18th` (the keyboard covers "Update expense" in the bill form). It fails the
  same way with main's unchanged `expenses/index.tsx` on this simulator, so this change did not cause it.
- tsc and lint are clean.

## Follow-ups / pitfalls
- Other custom `headerRight` views probably have the same iOS 27 problem. A tap on them

  here; if it shows, file a ticket to make them native items.
