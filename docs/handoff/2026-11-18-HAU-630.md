# HAU-630 Duo: month-pill jump lands under a collapsed title after unfolding upright

## What changed and why
- Cause (confirmed with scroll logs): the jump to row 0 scrolled to `topOffset`, the first scroll event's
  offset, recorded once per mount. A session launched folded records 0 (no large title there, HAU-629),
  so after unfolding upright the jump went to 0, the collapsed-title position. Same on `main`, not only PR #124.
  The reverse was wrong too: launched upright (-134), then folded, the jump went to -134 with no large title.
- `app/(tabs)/(paychecks)/index.tsx`: the first event now records the large title's height
  (`-y - pinTop`) instead of the offset, or `null` with no large title. The top for a jump is worked out
  for the current pose: `-(pinTop + height)` with a large title, 0 without. A session that never had a
  large title (only a Duo folded or on its side) uses `DUO_LARGE_TITLE_HEIGHT` 52.
- Measured first offsets: iPhone 17 Pro -168 = -(106 + 62); Duo upright -134 = -(82 + 52) at XS, XXXL
  and AX XXXL alike (the large title does not grow with Dynamic Type). The heights differ per device,
  so the learned height wins and the constant is only the Duo fallback. On a standard iPhone the target
  is the same number as before (pinTop cancels), so nothing changes there.

## Verified
- `bunx tsc --noEmit`, `bun run lint`; `.maestro/qa/` on Runner 1 (iPhone 17 Pro, Debug + Metro 8082): 6/6 in 10m 9s.
- Own Duo (iPhone Duo, iOS 27.1, duoctl v0.2.1), fresh install per walk, sample data, temporary
  `console.warn` logs (removed). With the old target swapped back in: hero y 93 after Nov (reproduced).
  With the fix: folded start → pin → upright → Nov: y 145, offset -134 (2/2, screenshot: expanded title).
  Upright start → pin → Nov: 145. Then fold → pin → Nov: offset 0, hero right under the bar. Then upright
  → pin → Nov: -134. Duo deleted afterwards.
- Dark only: the change is a scroll offset, no colours. Empty state has no list header, unaffected.
