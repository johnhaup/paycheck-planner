# HAU-858 Paychecks: collapsed header rests at one height after a pill jump (2026-11-26)

## What changed and why
- `app/(tabs)/(paychecks)/index.tsx`: a jump (pill, chart, Today) lands with the header all the way
  out (`collapse` 0). A short swipe forward from there (less than `collapseDistance`, about 240pt)
  collapsed it only part way, and since HAU-854 scrolling back never expands it, so it stayed
  part-collapsed mid-list: the pills and the Go Pro banner rested 19pt lower than in every other
  collapsed state. New `finishCollapse` worklet, run from `onEndDrag` and `onMomentumEnd` (not while
  a jump is running): a header with `0 < collapse` finishes collapsing (300 ms timing) up to the
  same cap as before, `lastPastTitle / distance`. Near the top that cap is where it already is, so
  the top-of-list expansion (HAU-854) is unchanged. A header a jump left fully out (`collapse` 0)
  stays out, as before.
- A momentum scroll that follows the drag overrides the drag-end timing (the scroll handler assigns
  `collapse`), and its own end runs it again.

## Verified (Runner 1, iPhone 17 Pro, iOS 27.0, dev build on Metro, sample data, free)
- `bunx tsc --noEmit`, `bun run lint` clean.
- HAU-854 QA's pill path in Light (two swipes up, tap Dec by point `26%,17%`, swipe `70%→45%`,
  swipe `45%→58%`). Go Pro banner edge at x=700 in the 3x screenshot: before the fix 427px vs 369px
  for a normal-scroll collapse (58px = 19pt, the bug); after the fix 367px (0.7pt, within the 1pt
  criterion; it stays there). The normal scroll path with Nov selected is 369px, the same as before.
- `.maestro/qa/paychecks.yaml` on Runner 1 (dev build): passed. Dark: same path, same 2px.
