# HAU-162: Settings at accessibility text sizes (2026-11-13)

## What changed
- `SettingsLinkRow`: at accessibility sizes (`useAccessibilityTextSize()`) the value goes under
  the label instead of beside it, and both use `AppWordWrapText`, so they wrap between words
  only and nothing ends in "…". Side by side, the value ("System default") took the row and
  squeezed "Language" to a few letters per line; the Pro row's "One-time purchase" was cut by
  `numberOfLines={1}`. The PRO badge (CSV export) sits between label and value, left-aligned.
  The chevron stays on the right, centred.
- `AppSegmentedControl`: segments had `height: 36`, which clipped the labels top and bottom. Now
  `minHeight: 36` plus vertical padding, so a segment grows with its text. At accessibility sizes
  the segments stack one per line (three 40pt+ labels do not fit side by side: "Syst…"); a label
  still wider than the row shrinks (to half size at most) before it is cut.
- The stack is in the shared control, so the Expenses filter and the expense form's segmented
  controls stack too at accessibility sizes (same reasoning as the earlier "one control, one
  behaviour" decision). Standard text sizes: no layout change anywhere.

## Verified
- `bunx tsc --noEmit` and `bun run lint` clean. Not run on a simulator: this machine has only the
  QA and Release Gate simulators, which are not the engineer's.

  segments by text and reads `selected`; neither changed.
- `text-size.yaml` has no Settings step; a screenshot of Settings at XXXL would protect this.

## Follow-ups / pitfalls
- `SettingsToggleRow` labels (Hide cents, reminders) still wrap as plain text beside the switch;
  a long single word could break at a letter at XXXL. Not in this issue; `AppWordWrapText` is
  the tool.
- A segment in a stacked track must not have `flex: 1`: in a column of unknown height Yoga gives
  a zero flex basis, so `flex: 1` is applied only in the side-by-side layout.
- `docs/AGENT_CONTEXT.md` gives the QA simulator's UDID as `1D1319E5-…`; on this machine
  `simctl` lists `Paycheck Planner QA 27` as `E48CA593-50B9-4752-8463-B4B436CE3A9A`. Left as is
  (may be per machine); look it up by name.
