# HAU-421: Quarterly bill row cuts off its last month (2026-11-16)

## What changed
- `ExpenseRow`: the meta line ("Due the 18th in Mar, Jun, Sep, Dec", "1st paycheck in Mar, Jun,
  Sep, Dec") had `numberOfLines={1}` at standard text sizes, so a quarterly bill lost its last
  month, often the one the user picked as First Month. It now wraps at every size, as it already
  did at accessibility sizes. Chose wrapping over a shorter form: no string changes, fixes all 45
  locales (longer month names and separators truncate sooner there), same call as the Income
  schedule line in HAU-366. `describeLinkSchedule` and the CSV/backup text are unchanged.
- Rows have no fixed height (`useGroupedRowStyles` pads, no height), so a two-line meta just makes
  that row taller; the amount column stays vertically centred.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean.
- Release build on `Paycheck Planner Dev`, sample data, scratch Maestro flow (not committed):
  Internet set to Due Day 18, Every 3 months, First Month Dec. Default size: "Due the 18th in
  Mar, Jun, Sep," / "Dec" on two lines, amount and "quarterly" centred beside it, other rows
  unchanged. Accessibility XXXL: stacked as before, all four months shown.
- `.maestro/qa/expenses.yaml` passes on that build. Other flows not run (only this row changed).

## For QA
- Expenses > a Brightline bill set to Due Day 18, Every 3 months, First Month Dec: the row reads
  "Due the 18th in Mar, Jun, Sep, Dec" whole, on two lines if needed. Other rows unchanged.
- No flow text changes; `expenses.yaml` matches rows by regex, so it is unaffected.

## Pitfalls
- A wrap can split the month list after a comma ("Sep," / "Dec"). Fine for a list; not worth
  non-breaking spaces.
- `expo run:ios --configuration Release` can exit 1 after a successful build and install: the
  final "activate Simulator window" osascript fails in the runner shell. The `.app` is installed;
  ignore that error.
- In a scratch flow, set Due Day after the chips: the number pad hides "Update Expense" and the
  tap lands on the keyboard. Maestro `takeScreenshot` with an absolute path fails; use
  `--test-output-dir`.
