# HAU-627 Duo: blank strip above the Paychecks summary after a fold, until the first scroll

## What changed and why
- Cause: the list kept the first scroll event's offset as its top (`topOffset ??= y`), which is right only
  under a large title, where iOS sends that event at mount. Folded there is no large title (since the
  large-title change for folded Duo) and no event at mount, so the first event came from the fold (y −58) and became
  the top. Loading sample data runs the jump to the top (HAU-64) to −58 while the real top is 0: a 58 pt strip.
- `app/(tabs)/(paychecks)/index.tsx`: the top is recorded only while there is a large title (`pinTop > 0`),
  and the jump to index 0 uses 0 when there is none. A list with no scroll event yet counts as being at 0,
  so the jump does not scroll at launch (the existing "not when it is already there" rule).

## Verified
- `bunx tsc --noEmit`, `bun run lint`; `.maestro/qa/` on Runner 2 (iPhone 17 Pro, Debug + Metro 8083): 6/6.
- Own Duo (iPhone Duo, iOS 27.1, duoctl v0.2.1), fresh install each time, issue's steps (folded, open,
  landscape, close, portrait, Try with sample data); "November · left over" frame y from `duoctl elements`:
  without the fix 151 (reproduced), with it 93, twice. Fresh install unfolded upright: data opens under
  the expanded large title; folding then: 93. Duo deleted afterwards.
- iPhone 17 Pro, fresh install + sample data: opens under the expanded large title (screenshot).
- Dark only: the app keeps its own theme and the fix has no colours.

## Follow-ups / pitfalls
- A session that starts folded and is opened upright records the top from the first event under the
  large title, which comes from the reflow; if the list is scrolled at that moment it is not the top.
  Not seen in testing; same class as this bug if it shows up.
- Reinstall for a fresh state on the Duo (Maestro does not run there): `simctl uninstall`, `simctl install`
  the app from `get_app_container <runner sim>`, `simctl launch ... --initialUrl http://127.0.0.1:<port>`.

## Merge of main
- `origin/main` merged in; `app/(tabs)/(paychecks)/index.tsx` conflicted because HAU-629 (#125) fixed the same bug. Took main's version (`topOffset.value ??= pinTop > 0 ? y : 0`); this branch's code change is now redundant, only this note remains.
