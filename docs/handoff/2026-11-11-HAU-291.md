# HAU-291: Android gate failed 8 of 9 flows @ bcff3bb (2026-11-11)

Read from the failed run's artifacts (`linear-runner/.stamps/worker-jobs/android-release-paycheck-planner-bcff3bb6ec91`):
the Gradle build was fine, the failures were two app bugs on Android and three iOS-only assumptions in the flows.

## App
- Expenses → Sort crashed the app on Android (`Invariant Violation: ActionSheetManager doesn't exist`, FATAL in
  logcat): `ActionSheetIOS` is iOS-only. Android now gets an `Alert` with the two sort orders not in use plus
  Cancel (an Android alert holds three buttons). iOS is unchanged.
- Toasts on Android (`app/_layout.tsx`, `Toaster` props, Android only):
  - they covered the toolbar and swallowed taps on the gear, Close and Mark all paid for 4 s (iOS draws them in an
    overlay window). `offset` now starts them under the 56dp toolbar.
  - sonner-native's positioner is a zero-height box with the toasts overflowing it. Android accessibility reports
    a zero-size parent and all its children as not visible, so TalkBack and Maestro never saw a toast or its Undo
    (logcat: "Skipping invisible child … Rect(0, 149 - 1080, 149)" on every hierarchy read).
    `positionerStyle: { bottom: 0 }` gives it a size; it is `box-none`, so touches still pass through.

## Flows (edited because the ticket is the gate; QA please review)
- "Back" → `"Back|Navigate up"` in smoke, paychecks, pay-date-detail, pro (Android's toolbar button).
- `large-title.yaml` tagged `ios`: Android has no collapsing large title.
- `accessibility.yaml` waits for "Name" instead of "Grouped" in the sort menu (on both platforms' menus).

## Verified
- `bunx tsc --noEmit` and `bun run lint` pass.
- NOT run on Android: the worker was outside its hours (13:22 Wed; next window 22:00). Everything above comes from
  the old run's logs and screenshots. Not checked on a device: that "Navigate up" is the back button's label,
  the Android alert's button text as Maestro reads it, and every step after the first failure of each flow
  (language picker, appearance segments, Erase all data, History, the Pro gates), which no Android run has reached.

## Lessons
- An Android gate failure needs `logs/device-logcat.txt` (grep `FATAL|ReactNativeJS`) and the step screenshot of
  each flow, not only the `[Failed]` lines: "text not visible" was a crash in one flow and a covered button in two.
- On Android a view with zero width or height hides its whole subtree from accessibility, even with
  `overflow: visible` drawing the children. Maestro's logcat lists it as "Skipping invisible child".
- Any `*IOS` API from react-native throws on Android in Release; guard with `Platform.OS`.
