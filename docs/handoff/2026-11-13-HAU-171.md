# HAU-171: native headers follow the in-app direction (2026-11-13)

## What changed and why

- New local Expo module `modules/layout-direction` (iOS only, autolinked from `./modules`):
  `setRTL(rtl)` sets `traitOverrides.layoutDirection` on every connected `UIWindowScene`.
- `app/_layout.tsx` calls it once at module load with `I18nManager.isRTL` (through
  `requireOptionalNativeModule`, so Android and a binary without the module do nothing). It runs
  again after the language picker's reload, because that reloads the JS.
- Cause: react-native-screens 4.30.1 forces only `semanticContentAttribute` on the stack's
  navigation bar (`RNSScreenStackHeaderConfig.mm`, `applySemanticContentAttributeIfNeededToNavCtrl`).
  The iOS 27 bar does not follow it; it follows the layout direction trait. The tab host already
  overrides that trait (`RNSTabsHostComponentView.mm`), which is why headers inside the tabs were
  right and the root stack's (Pay Date, Settings, paywall) were not.
- The bug needs the in-app language picker's reload (its PR is still open). On `main` alone the
  call sets LTR on an app that is already LTR: nothing visible changes until that PR merges.

## Verification

- `bunx tsc --noEmit` and `bun run lint` pass.
- Release build of this branch plus the picker branch's `app`/`src`/`app.json` diff, on a new
  `Paycheck Planner Dev` simulator (iPhone 17 Pro, iOS 27.0, `E802AB54-3D6E-4A0D-8266-9103784E7F47`).
- Arabic device, English picked: Pay Date has Back at the left and Mark all paid at the right;
  Settings and the paywall have Close at the right; Income by deep link has its title at the left.
- Control, same binary with the JS call disabled (bundle swap): Pay Date and Settings mirrored
  again, as in the issue.
- English device, Arabic picked: Pay Date (after a cold launch), Settings, paywall and Income by
  deep link are all RTL.
- `.maestro/qa/smoke.yaml` passes on that build. The full suite was not run.

## Not verified / follow-ups

- Alerts and native pickers in a mismatch: the scene trait probably moves them too, not looked at.
- A build of this branch alone (without the picker branch) was not made; the module is the same.

## Pitfalls

- Native change: needs a new binary. A JS bundle swap onto an older `.app` silently does nothing.
- Testing against an unmerged branch in one worktree: `git diff origin/main...<branch> -- app src app.json | git apply`, build, then `git apply -R`.
