# HAU-412: App Store keywords, November 2026

## What changed
Store listing metadata only, no app code. Subtitle and keyword field rewritten so no word repeats
across title, subtitle and keywords (Apple combines words across the three fields, so repeats waste
characters). Title "Paycheck Planner: Budget" unchanged everywhere.

- en-US (`ship.config.json`): subtitle "Bill tracker for every payday" (29); keywords exactly as the
  issue proposed (98 chars).
- en-CA: same subtitle; keywords add `paycheque` and keep `biweekly`. 101 chars with the full US
  list, so `savings` (diff 74, the hardest of the set) and `weekly` were dropped: 93 chars.
- en-GB, en-AU: same subtitle; `organiser`, `fortnightly`, plus `wages` (was in both old lists);
  100 chars each. Dropped from en-GB: `direct debit`, `rent`; from en-AU: `pay cycle`, `bill reminder`
  (now formed by subtitle "bill" + keyword "reminder").

## Not changed
The other 45 locales have their own localized keyword sets, not a translation of the English field,
so per the issue they stay. The Indic locales (bn, gu, hi, kn, ml, mr, or, pa, ta, te, ur) mix in
English words (`salary,bills,payday,expense,tracker`); a later ASO pass could check those against
Astro for India/Pakistan/Bangladesh.

## Verified
Lengths and no-duplicate words checked with a script (subtitle ≤ 30, keywords ≤ 100); the four files
parse as JSON. `bunx tsc --noEmit` and `bun run lint` pass. Not pushed to App Store Connect here: the
listing uploads with the next release (`bun run ship:ios` / store scripts, run by the runner).

## Follow-ups
Review Astro ranks for the `aso-candidate` phrases a month after 1.1.0 goes live.
