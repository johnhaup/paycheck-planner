# HAU-631 Duo: 41 pt blank strip above the Paychecks summary after a fold walk with data loaded

## What changed and why
- Cause (from scroll logs on a Duo): launched folded with sample data, the list sends no scroll event
  until the walk. The first one comes while the walk passes through the upright pose (pinTop 82,
  y −41, a passing offset), so HAU-629's `topOffset ??= pinTop > 0 ? y : 0` records −41. Back folded,
  the fold's header relayout runs the still-open opening jump to row 0, which scrolled to −41: the
  41 pt strip, until a drag. The upright pose before launch (step 1) is what makes the walk pass
  through upright (rotation sticks across folds), hence the 3/3 vs 1/8 rate.
- `app/(tabs)/(paychecks)/index.tsx`, `attemptJump`: the jump to row 0 uses 0 whenever there is no
  large title (`pinTopRef.current === 0`), whatever offset was recorded in another pose; a list with
  no scroll event yet counts as at its top (no scroll at launch, as before). The large-title path
  (standard iPhone, Duo upright) is unchanged.

## Verified
- Own Duo (iPhone Duo, iOS 27.1, duoctl v0.2.1), issue's steps exactly (open, portrait, close,
  portrait, fresh install, sample data, open, landscape, close, portrait). Before: reproduced, logs
  `topOffset -41 82` then `jump0 -41`. After, 2/2 runs: before/after screenshots differ only in the
  tab bar highlight (261 px); a second walk (upright, folded) also matches. Duo deleted.
- `bunx tsc --noEmit`, `bun run lint`; `.maestro/qa/` on Runner 1 (iPhone 17 Pro, Debug + Metro 8082): 6/6.
  Runner 1 Paychecks: large title expanded with the summary under it, as before.
- Dark only: the app keeps its own theme and the change has no colours. Empty state jumps to row 0
  too and takes the same path (0 without a large title).

## Follow-ups / pitfalls
- Still open (HAU-568/629): upright after a folded launch shows the large title collapsed; the
  recorded `topOffset` (−41 here, resting upright is −140) is wrong for that pose. A per-pose top
  offset would fix it.
- The opening jump stays "on" until the first drag, so any later header relayout (a fold) re-runs it.
  Any offset that jump uses must be right for the current pose.
