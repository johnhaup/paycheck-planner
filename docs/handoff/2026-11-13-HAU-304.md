## App
- `SettingsChoiceList` (language and currency pickers): a row's label and detail are now one text node
  (the detail is a nested `AppText` on a second line) instead of two sibling texts.
  Why: on an English emulator the System default row's detail is "English". iOS reads the row as one element
  ("System default, English"), so `tapOn: "English"` can only hit the English row. Android exposes each text
  as its own node, the detail is the first "English" in the list, and the tap picked System default, so
  Settings read "Language, System default" and `"Language, English.*"` failed in accessibility and settings.
  The 2pt gap between the two lines is gone; nothing else changes on screen.

## Lessons
- Maestro on Android matches each text node inside a pressable row; on iOS the row is one element with the
  joined label. A flow that taps a text which also appears as another row's secondary text hits whichever
  comes first on Android. Keep such a row's texts in one `Text`.
