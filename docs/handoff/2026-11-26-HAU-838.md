# HAU-838: Google Drive sync on Android

## What changed and why
- `@johnhaup/expo-cloud-sync` moved to v0.4.2, which fixes Android Sign out hanging on Google's revoke.
- The iOS-only gates are gone: `installSync` in `src/db/init.ts`, `CloudSyncProvider` + `SyncedStores` in `app/_layout.tsx`, and `SettingsSyncSection` in `app/settings.tsx` now run on both platforms. iOS code paths are unchanged.
- `SettingsSyncSection` picks its copy per platform (`IOS_KEYS` / `ANDROID_KEYS`, `settings.sync.android.*`). Android also shows **Sign in with Google** while signed out, and **Sign out of Google** plus **Sign out and delete Google Drive copy** while signed in. The switch, hint and states are the same as on iOS, and so is HAU-790's off and disabled switch while signed out.
- 16 new strings in all 45 locales. Google's localized "Sign in with Google" wording comes from memory; a native-speaker check would help (fi, hu, ru, ko and the Indic locales).
- No `app.json` change: the module's Android sign-in uses the package name and SHA-1 OAuth clients from HAU-778, with no plugin options.
- New test in `src/db/sync.test.ts`: an install that already had a budget before `installSync` first ran (an Android upgrade) merges it on its first sync.

## Verified (Linux worker, two `-read-only` instances of the `runner` AVD, both signed in to the test account)
- Release APK (x86_64, debug keystore). Signed out: switch off and disabled, Google hint, Sign in row. Sign-in went through the account picker and the drive.appdata consent, then showed "Last synced".
- A: Alpha Job. B, offline and before its first sign-in: Gamma Job and Gamma Rent. After B signed in, both installs had Alpha Job, Gamma Job, Beta Bill and Gamma Rent.
- A bill added on B reached A. Currency EUR set on A showed on B after a relaunch.
- Sign out: back to the signed-out state, and still signed out after a force-stop and relaunch. Signing in again kept the local rows.
- tsc, lint, `bun test` (39) pass.

## Pitfall
- The test account's Drive already held tombstones for the sample data (`demo-*` ids), from an Android Paycheck Planner sync on 2026-11-25 07:01. A fresh install takes the cloud row (v0.4.1 `fresh`), so "Try with sample data" followed by a first sign-in removed the sample. Fixed ids are the only ones that can collide; user rows are UUIDs. Test merges with hand-entered data, or clear the copy first ("Sign out and delete Google Drive copy").
- Two installs on one AVD: run `emulator -avd runner -read-only` twice. Both keep the account, and the module's device id is a random UUID per install.
