# HAU-357: Android release of `main` @ 3550a95 failed (build stage)

## What was wrong
- Two failures in one runner job (`~/runner/builds-android/paycheck-planner/2026-11-14-223838`):
  1. **Gate**: `paychecks` failed twice at "This paycheck" visible. Real app bug on Android: the
     Paychecks pinned header was pushed ~90dp down (`pinTop` = safe-area top + 44pt iOS nav bar) once
     the list had scrolled, leaving a blank band under the toolbar and covering the first card's header.
     After "Go to this month" Maestro tapped the card's centre and hit the chart's "Go Pro to plan a
     full year ahead" box underneath, so the paywall opened (John's screenshot). HAU-337 changed the
     flow but never ran it on Android.
  2. **Build**: `:app:signReleaseBundle FAILED`, with no Gradle error text in `release.log`. Not
     reproducible: the worker's keystore opens and signs (keytool, jarsigner), a plain
     `gradlew :app:bundleRelease` with it passes, and the runner's exact
     `eas build --platform android --profile production-local --local` (scratch copy, `autoIncrement`
     off so the remote versionCode stayed 2) built and signed a 71 MB AAB on 2026-11-15. Transient
     or environmental; no app change for it.

## What changed
- `app/(tabs)/(paychecks)/index.tsx`: `pinTop` is 0 on Android. Android's toolbar is opaque and the
  list starts below it, so the header pins against the list's own top edge. iOS is unchanged.

## Verified (Linux worker, `runner` AVD read-only on port 5590, x86_64 Release APK)
- Before: `paychecks.yaml` failed at the same step; hierarchy showed the chart at y 843-1311 over the
  card at 1172-1382.
- After: `paychecks`, `smoke`, `income`, `expenses`, `settings` all pass (`--exclude-tags ios`).
  Screenshots: after "Go to this month" the card sits right under the chart; scrolling collapses the
  chart into pills pinned directly under the toolbar.
- `bunx tsc --noEmit`, `bun run lint`.
- Not run: iOS (no Mac here). The iOS value of `pinTop` is untouched.

## Follow-ups
- linear-runner: the release log drops Gradle's stderr ("unknown error"), so a signing failure can't
  be diagnosed after the fact. Keep `EAS_LOCAL_BUILD_SKIP_CLEANUP` or `--stacktrace` output on failure.
- The job went on to the build stage although the gate failed `paychecks` twice; check the gate's
  exit code handling in the `~/runner` release job.

## Lesson
- iOS-only geometry (nav bar height, safe-area top used for a list that runs under the bar) must be
  0 on Android, where the list starts below an opaque toolbar.
