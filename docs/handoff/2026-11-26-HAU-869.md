# HAU-869: form fields fade in and out, the rest springs (Income and Expense forms)

## What changed
- New `src/components/AppFormSection.tsx`: an `Animated.View` with `ROW_ENTERING` / `ROW_EXITING` /
  `LAYOUT_SPRING` from `src/constants/motion.ts`. No numbers of its own.
- `app/income-form.tsx`: the semi-monthly block and the First pay date block are each a keyed
  section (so a frequency change remounts them and they cross-fade); the save button is a section so
  it springs to its new place. The form sits in `<LayoutAnimationConfig skipEntering>` so the sheet
  does not fade its fields in on open.
- `app/expense-form.tsx`: every field group below the Bill / Set-aside control is a section (set-aside
  hint, payee, amount, goal / link (keyed), icon, one-time paycheck, linked source, due day, How often,
  First month / Starting with, Which paycheck, save button). Layout springs only move a view that has
  `layout`, so everything that can be pushed down needs to be wrapped, not just the block that appears.

## Verified (Runner 1, iPhone 17 Pro, iOS 27.0, dev build, sample data, dark)
- Recorded at 30 fps with `simctl io recordVideo`: Weekly → Semi-monthly → Bi-weekly and
  None → Brightline Co. → None. Fields fade over ~5 frames, the save button moves over ~6 instead of 1.
- Reduce Motion on (`defaults write com.apple.Accessibility ReduceMotionEnabled`, cold start): each
  change lands in one frame, nothing half-shown or overlapping.
- `.maestro/qa/income.yaml` and `expenses.yaml` pass; tsc and lint clean.

## Not verified / follow-ups
- Android: `ROW_ENTERING` is undefined there (HAU-810), so new fields appear at once; the layout spring
  and exit fade still run. Not run on Android.
- Light mode not re-checked: the change adds no colour.
- The chip colour still switches at once (the issue noted it; the motion rules say choice labels switch
  colour at once, so left as is).
- While a block fades out, the button springing up passes over it for a few frames (same as list rows).

## Pitfall
- Recording a whole Maestro run makes transitions hard to find; open the form in one flow, then record
  only a second flow with the taps. `simctl` video is variable-rate: resample with `ffmpeg -vf fps=30`.
