# HAU-451 Android build failed @ df7f162 (submit)

## What failed
Two separate problems in the Android release run `2026-11-16-121920` (linux worker), the same
pair as the previous "Android build failed" ticket, one step further on:

1. **Gate: `expenses.yaml` failed twice** at `".*Internet.*Due the 18th.*" is visible`. The app
   was right (the issue's screenshot shows Internet with "Due the 18th"). iOS reads a bill row as
   one element, so a regex across name, schedule and unit matches there. On Android the row is
   separate text elements ("Internet", "Due the 18th", "monthly"), so it never can.
2. **Submit: "The Google service account cannot submit this app."** Still no Play Console app for
   `com.johnhaup.paycheckplanner`. Nothing in the repo can fix this; see follow-ups.

## Change
`.maestro/qa/expenses.yaml` only, three asserts; the app is untouched:
- Due day set: `(.*Internet.*)?Due the 18th.*` (whole row on iOS, the schedule line on Android).
- Due day cleared: the old cross-row regex stays inside `runFlow: when: platform: iOS`. Android
  waits for "Due the 18th" to go, then asserts `2nd paycheck each month` `below: "Internet"`
  (Car Payment has the same line, but above Internet).
- Yearly: `(.*QA Water.*)?yearly.*`.

## Verified

  passes every step, including the three changed ones.
- `bunx tsc --noEmit`, `bun run lint`: clean.
- Not run on iOS (linux worker). The iOS regexes match everything the old ones did.

## Lessons
- A Maestro text regex matches one element. Never span a bill row's name, schedule and amount in
  one regex in a shared flow: match one text, and tie it to the row with `below:` on Android.
- First run after a cold emulator boot failed on a "Pixel Launcher isn't responding" dialog over
  the app. Wait ~20 s after `boot_completed` (or dismiss it) before running a flow by hand.
