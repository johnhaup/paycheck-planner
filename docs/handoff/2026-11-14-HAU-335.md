# HAU-335: flaky gate flow settings-text-size (2026-11-14)

## Cause (from the gate's artifacts on mbp-512, `~/runner/builds/paycheck-planner/2026-11-14-102603/`)
The failing step was not in the flow's body but in `subflows/approve-deep-link.yaml`, which it runs from
`onFlowStart`. `settings-text-size` was the first flow on shard 3's freshly erased simulator, so it got the
"Open in Paycheck Planner?" alert. Maestro tapped Open, the alert closed, and the app stayed on the Paychecks
welcome screen: the link that raised the alert never navigated to Income, and the 30 s wait for "No income yet"
ran out. Whether iOS dropped the link or the app ignored it is not known (no app log in the artifacts); it has
arrived every other time. Any flow that is first on a shard can fail this way, not only this one.

## Change (flows only, no app code)
- `subflows/approve-deep-link.yaml`: the Open tap is trusted only for the approval. When the alert is up: tap Open,
  wait for it to go, send `paycheck-planner://income` again (an approved simulator shows no alert), then require
  "No income yet" as before.
- `settings-text-size.yaml`, language picker: my first verification round hit a second flake at load 840. After
  `scrollUntilVisible: English` (`centerElement`) the list was still moving, English ended under the sheet header,
  the tap hit the header and the picker stayed open. The step now picks rows that need no scroll: Català
  (row reads "Idioma, Català"), then "Per defecte del sistema" back (row reads "Language, System default").
  Same coverage (the stacked row opens the picker, a pick comes back to the row), twice, and no scroll.
  Waits there are 15 s.

## Verified
- `maestro check-syntax` on both files, `bunx tsc --noEmit`, `bun run lint`.
- On mbp-1tb, the gate's Release build of 5c9c0d5 (copied from mbp-512's DerivedData), `Paycheck Planner Release
  Gate` erased, booted and reinstalled before every run so the alert path runs each time, while `text-size` and
  `smoke` looped on `Paycheck Planner Release Gate 2`:
  round 1 (subflow fix only) pass, fail (the language step, load 840), pass; round 2 (both fixes) 3 of 3 in
  a row at load 520-650, Open tapped and the link re-sent in every run, the looped flows green.
- Not run: the whole sharded suite, Android (the flow is tagged `ios`; the subflow change has no iOS-only step).

## Pitfalls
- A flaky-flow ticket's failure line can name a step of the `onFlowStart` subflow. Read `commands.json` and the
  screenshot in the gate's `maestro/<stamp>/<flow>-shard-<n>/` on the machine that ran it (coordinator.log says
  which) before touching the flow.
- At XXXL a `scrollUntilVisible` with `centerElement` can leave the target under a sheet header; Maestro still
  calls it visible and taps the header. Prefer a target that needs no scroll.
- `language-direction.yaml` scrolls to English the same way (normal text size, so less travel); same fix if it flakes.
- The QA simulator's UDID differs per runner Mac (`BF12E0EB…` on mbp-1tb); look it up by name.
