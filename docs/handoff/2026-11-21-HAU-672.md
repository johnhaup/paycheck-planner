# HAU-672 Motion and feel pass

## What changed and why
- `src/constants/motion.ts` holds every duration, spring and fade (`DURATION`, `SPRING`, `TIMING`, `FADE`,
  `PRESSED_SCALE`, `ROW_ENTERING` / `ROW_EXITING`, `LAYOUT_SPRING`). Rules in brain `decisions.md`
  (2026-11-21 "Motion rules"). Every spring carries `energyThreshold: 1e-4` so it ends when it looks done.
- Money counts instead of snapping: `useCountUp` (replaces the JS-thread `useAnimatedNumber`) runs a 350 ms
  Reanimated timing on the UI thread and hands React each frame's progress; several numbers in one line
  count together. `AppHeroAmount` and the new `AppCountUpText` use it: the Paychecks hero and
  "in · assigned" line, a card's pay amount, "$X left" and "Short by", the pay date summary line and
  "Short by", the Expenses monthly total, Income "per month". The final text is the `accessibilityLabel`,
  so VoiceOver and Maestro read the value it counts to. Under Reduce Motion it fades out and back in.
- `AppSegmentedControl`: one pill springs between measured segments (row and stacked); segments dim on press.
- `AppToggle`: thumb springs, track colour fades, dims on press. `AppCheckCircle`: fill fades, mark pops in.
- `PaidProgress` segments fade to green; `MonthBarChart` bars spring to a new height.
- `AppFab` shrinks while held and pops back; its bounce in/out timings moved to the theme.
- List cells (`AppAnimatedListCell`, `PaycheckExpenseRow`) use the shared fade and layout spring.
- Haptics: `withUndo` gives success (delete, move, mark all paid, restore, erase); saves of the expense,
  income, amount sheets and the one-time bill give success; `toastError` (new) pairs every error toast
  with the warning haptic.
- Left alone: `HEADER_EXPAND_MS` in Paychecks (matched to UIKit's animated scroll, not a motion choice),
  native sheets and tab transitions, keyboard, the card list itself, paywall.

## Verified
- `bunx tsc --noEmit`, `bun run lint` clean. Core suite `.maestro/qa/` 6/6 on Runner 1 (dev build, Metro 8082).
- Before/after recordings of one scratch flow (assign Rent on a pay date, mark paid, remove, Expenses filter,
  Settings theme) on main and on this branch; frame grabs show the hero counting (-$647.95, -$766.93, -$767.00).
- Reduce Motion (`com.apple.Accessibility ReduceMotionEnabled` via `simctl spawn defaults`): the hero and its
  meta line fade out and in with the new value, no counting.
- Dark and light (Settings theme pill), empty state (Welcome) checked by screenshot.

## Pitfalls
- The first engineer run on this ticket hit its turn cap before committing; nothing of it survived but the
  brain entry. Commit early on long polish tickets.
- Marking a bill paid changes no amount (left = pay − assigned); to see a count, assign or remove a bill.
- Not checked: dropped frames in a Release build (no Release build allowed here) and haptics (no device).
