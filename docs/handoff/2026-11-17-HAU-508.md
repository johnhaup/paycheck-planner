# HAU-508 Flaky gate flow: paychecks, smoke (2026-11-17)
## What failed (gate @ 315279e, artifacts in `~/runner/builds/paycheck-planner/2026-11-17-000212`)
No wait step timed out. Both flows ran on shard 2 (`Paycheck Planner Release Gate 2`) and both
ended with `maestro.DeviceUnreachableException: Device became unreachable during isScreenStatic`:
- **paychecks**: `tapOn: "Income"` (the tab return) started 00:10:58 and tapped at 00:10:59.7.
  The Maestro XCTest driver on that simulator then logged nothing for 88 s and, at 00:12:28,
  xcodebuild reported "The test runner exited with code 75 before finishing running tests"
  (host log: `log show --predicate 'processID == 37909'`). Maestro's next request got EOF, then
  connection refused on the driver's port.
- **smoke**: next flow on the same shard, 9 s, failed in `setPermissions` before its first step:
  Maestro does not restart a dead driver between the flows of one shard.
- The other three shards kept passing. The host load average was in the hundreds. Nothing in
  `CoreSimulator.log` or any agent transcript touched Gate 2, and there is no app crash report.

## Change (`.maestro/qa/paychecks.yaml` only; the app is untouched)
- The Arabic and Japanese relaunches are inside `retry: maxRetries: 2`, the follow-up the previous
  flaky-flow ticket left for this flow (a launch can fail outright under gate load).
- Nothing else: every wait in both flows is already an `extendedWaitUntil` of 10 to 60 s, and no
  step in a flow can bring back a driver process that has exited. `smoke.yaml` is unchanged.

## Verified
- QA 27 (iOS 27, the Release build QA installed 2026-11-16 22:16, after the last commit that
  changed app code): `paychecks` + `smoke`, 3 runs in a row, all passed (1m 44s/39s, 1m 27s/29s,
  1m 29s/30s) while `settings` looped on `Paycheck Planner Dev` (5 passes) and the load average
  was 380 to 400.
- `maestro check-syntax`, `bunx tsc --noEmit`, `bun run lint`: clean.
- Not on the `Release Gate` simulators: they belong to `gate.sh` alone (AGENT_LESSONS).
- The driver death could not be reproduced, and the `retry` path itself never ran.

## Follow-ups
- linear-runner (not this repo): a flow that fails with `DeviceUnreachableException`, and every
  later flow of that shard, is a dead driver, not a flaky flow. The retry already covers it;
  it should not file a "Flaky gate flow" ticket, because there is nothing in the flow to harden.
- `settings` and `pro` still relaunch mid-flow without `retry`.

## Lessons
- Read `report.xml` before touching a flaky flow: `DeviceUnreachableException` plus a following
  flow that fails in seconds on the same shard means the XCTest driver died, and the step it
  died on is incidental.
