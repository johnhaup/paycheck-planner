- 2026-11-05 (HAU-154): Arabic month chart amounts read "$4.8k US" and "$2,475k US-". `formatCompactMoney` put a plain `-` in front of the formatted string and a `k` after the last digit; in Arabic the string is RLM + number + NBSP + "US$", and the left-to-right `k` joined the number to "US" in one run, while the `-` before the RLM went to the far end. It now formats the signed value (the locale's own minus sign and placement, as `formatMoney` does) and, when the string carries a right-to-left mark, adds an RLM after the number (after the `k` when there is one), so Arabic reads "$US 4.8k" and "$US -2,475k". Hebrew negatives move from "$ 2,475k-" to "$ -2,475k"; English strings are identical; Dutch and Swedish negatives now match the rest of the app ("€ -2,5k", U+2212). Verified with tsc, lint and a throwaway harness that ran the old and new function on macOS's `NumberFormatter` and Bun's ICU and read the display order back from CoreText (the old code reproduced both strings from the ticket); not seen on a simulator.

- 2026-11-04 (HAU-167): on an Arabic device with English picked in the app, text sat at the right edge of its box in an LTR layout. React Native 0.88 on iOS only writes a paragraph alignment when the style sets one or the layout is RTL (`RCTAttributedTextUtils.mm`); in an LTR layout with nothing set, UIKit's natural alignment follows the app's iOS language. `AppText` now defaults to `textAlign: "start"` (`center` and `style` still override), the toast title and description get the same, and `AppInput` sets `left`/`right` from `I18nManager.isRTL`. Inputs were not in the ticket: the same code path says they follow the device too, in both mismatched directions. Inert on `main` until HAU-152 lands (no `CFBundleLocalizations`, so iOS is always English). Verified with tsc and lint and by reading RN's source; not seen on a simulator.
