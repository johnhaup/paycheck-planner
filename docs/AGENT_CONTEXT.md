## Lessons and pitfalls (do not repeat)

- iOS launch arguments `-key value` land in the NSUserDefaults argument domain, so React Native's `Settings.get(key)` reads them with no native module (HAU-78). Maestro passes `launchApp: arguments:` keys verbatim as `key value` (no dash), so the flow keys must carry the dash themselves: `"-proStoreMock": true` reaches the app as `-proStoreMock true` (checked in the process argv with `ps`); an undashed `proStoreMock: true` silently leaves the mock off and Buy hits the real sandbox.
- An Expo SDK upgrade can silently break native-feeling behaviour that no type check sees. HAU-52 passed QA with the collapsing large title and pinned overview both broken; John found it in TestFlight. Those two are now a must-check on every QA run and a flow (`large-title.yaml`).
- Large titles only collapse when the scrolling view is the screen's root and uses `contentInsetAdjustmentBehavior="automatic"`. A FlatList wrapped in a View loses it.
- StoreKit testing: the `.storekit` configuration reaches the simulator only through Xcode's run action. From a `simctl` launch, Buy goes to the real App Store sandbox and raises a "Sign in to Apple Account" alert that Maestro cannot see and that survives `clearState` relaunches, so every later flow fails at Welcome. That kept purchase steps out of `.maestro/qa/` until HAU-78; the gate now buys on the mock store (`-proStoreMock`). A failed mock flow that reaches the real Buy leaves the same alert, so dismiss it (`tapOn: point: "33%,60%"`) before re-running.
- The App Store Connect product stays "Missing Metadata", and purchases fail in TestFlight, until a review screenshot of the paywall is attached.
- `expo run:ios --device <udid>` ends with an `osascript` call that hangs while a macOS Automation prompt waits on John's desktop. For a Release build to install by hand, build with `--device generic --output <dir>` and `simctl install` instead.
- Dev builds load JS from Metro on 8081 only after `clearState` (it wipes `RCT_jsLocation`). Start Metro on 8081 before running the suite against a Debug build; a Release build needs no Metro (it has `main.jsbundle` in the app container).
- Maestro: Settings rows with a chevron have labels ending in ", " so match with `".*Erase all data.*"`. The month chart columns match only by their accessibility label (`"September 2027, $5k left"`). Sample data comes from "Try with sample data" on the empty Paychecks tab. Past paychecks' title is "Past paychecks", not "History".
- A fresh install is Dark whatever the OS appearance says (`themeStore` default).
- Never open the Xcode app from an agent shell. A GUI Xcode holding a worktree's workspace leaves dialogs on John's screen when prebuild regenerates `ios/`.
- Flows in `.maestro/qa/` run on a loaded Mac in the release gate: use `extendedWaitUntil` on the element the next step needs with 10-20 s timeouts, never fixed sleeps. A flow that only passes on an idle machine is a flake.

- A gate ticket whose log has no `[Failed] <flow>` line and no `report.xml` never ran a flow. Read `~/Projects/linear-runner/.stamps/gate-<slug>-<date>/maestro.log`: `IOSDriverTimeoutException` / "iOS driver not ready" or "Device … is not connected" mean Mac load or a dropped simulator, not an app regression. Check `~/Library/Logs/linear-runner.log` for an earlier PASS at the same sha and for another gate starting the same minute (HAU-99).

- The `<App> Release Gate` simulator belongs to `gate.sh` alone: no agent builds, installs, launches or runs Maestro on it, even when no gate is running at that moment, because a long `expo run:ios` outlives the check and the next tick's gate starts on top of it (HAU-102). A gate whose first try fails with `DeviceUnreachableException` or a screen the flow never navigated to, and whose retry passes, points at a second user of the simulator: grep the agent transcripts in `~/.claude/projects/*/` for the gate simulator's UDID.
- Undo toasts (`withUndo`, sonner-native default) dismiss themselves after 4 s. In a flow, tap Undo straight after `extendedWaitUntil: visible: "Undo"` with no screenshot or other step in between: under gate load a single step can take 2-10 s (HAU-102).
